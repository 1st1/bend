# Architecture

Bend is a native macOS prototype combining SwiftUI browser chrome, AppKit windows, and system WebKit pages in nested tiling layouts.

## Development signing

[build-app.sh](../scripts/build-app.sh) packages and signs Bend.app, using `BEND_SIGNING_IDENTITY` when set and Yury's Developer ID Application certificate otherwise.

Requires macOS 14 or newer and a Swift 6 toolchain (Xcode or Command Line Tools). From the repository root, build and open the signed app:

```sh
./scripts/build-app.sh --open
```

On another Mac, select an installed Apple-issued signing identity:

```sh
BEND_SIGNING_IDENTITY='Developer ID Application: Your Name (TEAMID)' ./scripts/build-app.sh --open
```

The certificate's Apple intermediate must also be installed; Developer ID G2 certificates require Apple's Developer ID G2 intermediate. `security find-identity -v -p codesigning` should list the identity as valid. For development without the packaging script's signing step, open [Package.swift](../Package.swift) in Xcode or run `swift run Bend`.

The build explicitly supplies the installed SDK version to the linker while retaining macOS 14 as the deployment target. This prevents SwiftPM from stamping the deployment target as the linked SDK and making AppKit render legacy controls and toolbar chrome.

The package and executable product are named Bend. The bundle retains `dev.yury.browse.prototype`, the `BrowsePrototype` data directory, and existing window autosave keys so renaming does not create a separate profile. Internal Swift module names and `browse://` addresses remain stable. The legacy `BROWSE_SIGNING_IDENTITY` override is honored when the Bend override is unset.

The script enables Hardened Runtime and verifies the signature before reporting success and does not fall back to ad-hoc or self-signed signing. Apple-issued development or Developer ID signing uses a stable team partition for Keychain access; switching identities can still require one new approval. A self-signed identity supplied explicitly through the override does not prevent recurring WebCrypto prompts because macOS assigns it a per-build code-hash partition. The build does not alter Keychain access lists or key data.

Packaging creates a separate bundle in a temporary directory under `dist`, then signs and verifies it before replacing the installed bundle by rename. It does not overwrite the executable mapped by a running Bend process. Signing or verification failure leaves the previous build intact; publication failure restores the previous bundle. The script leaves Bend running and asks for a restart to use the new build. Extension packages, enablement, grants, and WebKit data remain outside the app bundle.

## Application icon

The app uses the supplied painted Bend artwork, with the untouched 2048×2048 source preserved in [BendIcon-original.jpg](../Assets/BendIcon-original.jpg).

The generated icon uses a top-aligned square crop that trims extra wall below and equally at the sides, vertically centering the B's main body rather than its trailing brush stroke.

[generate-app-icon.swift](../scripts/generate-app-icon.swift) renders the artwork with rounded corners, transparent margins, and a subtle shadow into standard and Retina icon sizes. Run `swift scripts/generate-app-icon.swift` on macOS to regenerate [AppIcon.png](../Assets/AppIcon.png) and [AppIcon.icns](../Assets/AppIcon.icns). [build-app.sh](../scripts/build-app.sh) copies the ICNS into bundle resources and sets the icon entry in Info.plist before signing.

## Production installer

[build-prod.sh](../scripts/build-prod.sh) creates a signed, notarized drag-to-Applications DMG, separate from the fast [[architecture#Development signing|development build]].

Run `./scripts/build-prod.sh` from a logged-in macOS desktop session. It defaults to the saved `bend-notary` Keychain profile; `--keychain-profile NAME` or `BEND_NOTARY_PROFILE` selects another. Signing uses the same Developer ID identity override as the development build. Credentials stay in Keychain. The script builds the host architecture and names the installer `dist/Bend-VERSION-ARCH.dmg` from the app plist and executable, without implying a universal build.

A private copy of the app receives a timestamped Developer ID Application signature, is submitted with `notarytool`, and has its accepted ticket stapled and validated before packaging. The development bundle stays separate from this stapled copy. [render-dmg-background.swift](../scripts/render-dmg-background.swift) draws a Retina installer background with instructions and an arrow. [layout-dmg.applescript](../scripts/layout-dmg.applescript) uses Finder to save a fixed icon-view window with Bend and an Applications shortcut. Finder automation may require macOS consent on first use.

The compressed, read-only DMG is signed, notarized, stapled, and checked by Gatekeeper and disk-image verification before replacing an existing installer. App and DMG submission results and service logs remain under `dist/notary-*`. Rejected or timed-out submissions and failed checks abort publication. Stapling retries briefly while Apple's ticket propagates. Cleanup detaches only the script's mounted image; detach failures retain its working files for recovery. [[tests#Production installer publication]] checks failure preservation and sequencing with isolated command stand-ins; real notarization and Finder rendering require the native production run.

## Application shell

[BrowseApp.swift](../Sources/Browse/BrowseApp.swift) owns menus, keyboard shortcuts, and application lifetime. [BrowserWindows.swift](../Sources/Browse/BrowserWindows.swift) owns the browser windows. [BrowserView.swift](../Sources/Browse/BrowserView.swift) renders a dark sidebar, vertical tabs, pane controls, and start pages.

Both built-in start pages show a centered, muted-gray keyboard shortcut reference matching the browser's menus. Action labels and right-aligned keys form two columns, grouped by task with whitespace; shorter panes scroll the list. Tab, window, and pane shortcuts appear by default. A centered, subtle gray See more pill reveals navigation, find, page zoom, history, and settings shortcuts; See less collapses them again. Expansion and collapse smoothly resize the list, fade the extra groups, and rotate the chevron. The pill keeps a stable width and animates as one unit while its labels crossfade; Reduce Motion disables these animations.

The sidebar presents one continuous column of tabs without group headings or group creation. Each tab contains one or more browser panes. Selection changes the displayed tab; closing the final tab creates a replacement. The sidebar can be resized or hidden, with session-save errors shown at the bottom only when needed.

The sidebar header right-aligns downloads beside the sidebar toggle and hides downloads when its list is empty. The header sits above the clipped sidebar scroll view and shares the tab list’s insets, aligning the toggle’s right edge with the tab rows. Docked rows use ten points on the left and four on the right; the canvas’s six-point gap completes the matching visible margin. Floating sidebars use ten points on both sides. Command-T and the File menu create tabs; there is no plus button. Panes use six-point outer margins and divider gaps. When the sidebar is hidden, downloads remains beside the sidebar toggle near the window controls in the upper-left visible pane, including when a different pane is zoomed. Both layouts keep Downloads on the left and the sidebar toggle on the right, with matching 28-point controls and a two-point gap. [[tests#Downloads with collapsed sidebar]] covers their visibility, sizing, and spacing.

Each pane has one compact title row with Back/Forward, reload/stop, extensions, zoom, and close controls, using shared [[architecture#Toolbar button styling]]. The split-pane button is omitted; splitting remains available through menus and shortcuts. Reload focuses its pane and becomes stop while loading; it is disabled on start pages. The persistent address row is replaced by the [[architecture#Location popup]]. [[architecture#Pane navigation controls]] describes toolbar visibility and navigation behavior; tab creation remains in the File menu and Command-T.

[BrowserWindows.swift](../Sources/Browse/BrowserWindows.swift) attaches an empty unified native toolbar to give the traffic lights standard toolbar-height spacing. AppKit manages their placement through resizing and full-screen transitions; their native size and position do not change when the sidebar toggles. Sidebar controls and pane titles share the traffic lights’ fixed vertical centerline, accounting for the pane’s outer margin. The transparent titlebar has no separator or shared toolbar actions. [[tests#Window control alignment]] covers sidebar toggles and window resizing.

## Fullscreen chrome

[BrowserWindows.swift](../Sources/Browse/BrowserWindows.swift) auto-hides the empty native toolbar in fullscreen so it cannot permanently cover the browser’s pane headers and sidebar controls.

[FocusWebView](../Sources/Browse/BrowserStore.swift) enables WebKit's HTML Fullscreen API for browser pages, including replacement and supplied browser WebViews. Video players can use their fullscreen button or double-click handler without site-specific code. WebKit retains its native user-gesture and iframe permission checks and manages element fullscreen separately from Bend's window fullscreen. [[tests#Page fullscreen availability]] checks the page-visible API.

The empty unified toolbar is hidden before fullscreen entry, leaving AppKit's compact native titlebar for top-edge rollover instead of a tall empty toolbar row. The same toolbar becomes visible again after exit or failed entry, preserving windowed traffic-light alignment. Completed transition notifications update a transient per-window fullscreen state. [BrowserView.swift](../Sources/Browse/BrowserView.swift) then removes the collapsed sidebar’s traffic-light spacer and the narrow sidebar’s extra window-control row, while retaining its sidebar toggle and pane actions. Location popups dismiss before either transition so their anchors cannot remain at obsolete window coordinates. No page or WebView is replaced. [[tests#Fullscreen chrome transitions]] covers real fullscreen entry and exit.

## Browser windows

[BrowserWindows.swift](../Sources/Browse/BrowserWindows.swift) owns independent native browser windows. File → New Window and Command-N create a blank tab in a new window with its address popup focused.

Each window owns its store, tab selection, pane controllers, sidebar sizing, zoom, closed-item stack, address panel, and saved frame. [BrowseApp.swift](../Sources/Browse/BrowseApp.swift) routes tab, pane, navigation, and history commands to the key browser window, falling back to the last active browser while a popup or Settings is key. Command-W closes the focused utility window, including Settings, instead of falling through to the last browser; the address popup retains its cancel-new-tab behavior. In a browser window, Command-W closes the focused pane while other panes or tabs remain; on the final pane of the final tab it closes that window if another browser window remains. In the sole browser window it replaces the closed page with one blank pane and focuses its address popup, retaining the closed page for reopening. Explicit native window closure still closes the window. [[tests#Closing the last browser pane]] covers this boundary and isolation from other windows. Closing a browser window stops and releases only its page controllers. Live tabs and panes can move between open Bend windows through [[architecture#Cross-window dragging]].

One retained root store owns history and UI preferences, including after its original window closes. Other [BrowserStore.swift](../Sources/Browse/BrowserStore.swift) instances delegate reads and writes to it and forward observation, so live history results and appearance changes reach every window. Settings and the extension manager are shared; normal website views use WebKit's shared default data store. [[architecture#Session restoration]] preserves each window's layout independently.

## Sidebar media player

[SidebarMediaPlayer.swift](../Sources/Browse/SidebarMediaPlayer.swift) places a native Now Playing card below the tab list, controlling media in foreground or background panes. Playback controls preserve tab selection; choosing a source reveals its pane.

[MediaSessionBridge.swift](../Sources/Browse/MediaSessionBridge.swift) installs one document-start script per content controller in the page world, including subframes. It forwards native Media Session action registrations unchanged while retaining callbacks for generic play, pause, previous, and next controls. Audio/video elements, including dynamically inserted players, open shadow roots, and off-DOM players started through the native play method, provide fallback play and pause. The play wrapper preserves the original return value and exceptions. Detached players remain resumable while paused and are discarded when ended, failed, or emptied; removing a previously attached player still retires it. Muted autoplay alone does not create a player. Sites declaring a playing Media Session can expose controls without a visible media element. Unsupported buttons remain disabled; this does not use site-specific selectors or simulated system keys.

Track titles and artists come from Media Session metadata, falling back to the active element's accessible label or title, then the document title and site. Playback events and metadata assignments send deduplicated updates. While a frame has an active or resumable session, [PageMediaController.swift](../Sources/Browse/PageMediaController.swift) refreshes it every two seconds to detect in-place metadata changes and detached frames. Idle documents have no refresh timer. The card uses the pane favicon, with no separate artwork download.

The card always reserves its progress bar and time row; finite-duration media shows elapsed and total time. [MediaProgressSlider.swift](../Sources/Browse/MediaProgressSlider.swift) draws a thin rounded track with a light filled portion and no separate thumb, matching the macOS volume bar. Native cell tracking and slider accessibility remain available. The control owns mouse routing so AppKit’s internal hosted input view cannot bypass drag boundaries. Arrow-key and accessibility adjustments seek in five-second steps and commit immediately; dragging commits on release. HTML media supplies current time, duration, and playback rate; handler-only players can supply Media Session position state. Native interpolation keeps the visible bar moving between existing two-second refreshes without extra page polling, and stops during pause, seeking, or reported buffering. Unknown or infinite durations show an empty, disabled track with dash time labels. Missing timing between tracks keeps the same bar and time-row geometry, preventing the card and playback controls from jumping. Seeking uses the site’s seek-to handler when registered, otherwise a seekable HTML media element; native and frame-side checks reject invalid targets. Scrubbing sends one seek on release and keeps commands bound to their source pane.

The card shares browser-pane chrome: a fixed-height glass header follows the pane header appearance and rim-clipping settings, with the favicon beside a single-line, tail-truncated title and a dismiss button. Its [[Sources/Browse/BrowserView.swift#PaneChromeBackground]] applies the shared top- and bottom-rim clipping amounts while preserving side highlights, matching [[architecture#Pane materials]]. [[Sources/Browse/BrowserView.swift#PaneBodyBackground]] hides the controls surface's own top rim, leaving only the title header's adjustable bottom rim at their boundary. Clipping changes apply live without changing card geometry. Centered artist/site metadata and playback controls sit below. Left and bottom insets use the pane gap; the adjacent canvas supplies the right-side gap, with no extra trailing padding.

Only the card's dismiss button hides when the pointer leaves; hovering anywhere in the card reveals it. Its layout space stays reserved, and it cannot receive clicks or accessibility focus while hidden. Playback and source-picker controls stay visible. The dismiss fade matches the pane toolbar's 100 ms transition and respects Reduce Motion.

Messages are page-controlled input. Native routing uses WebKit's originating WebView and frame, bounds strings and session counts, strips control and directional formatting characters, and accepts only supported commands. Commands use structured arguments, target the recorded frame, and check its document and player identities before invoking a callback. Main-document changes, frame departure, WebView replacement, process termination, and closure discard obsolete sessions. The page-world bridge grants no native capability beyond reporting player state; media commands originate from native controls.

[WindowMediaCoordinator.swift](../Sources/Browse/WindowMediaCoordinator.swift) selects the most recently started playing source, retaining paused sources for resuming. Selection stays with the current source through pauses and metadata changes until it is removed, dismissed, explicitly changed, or another source starts playing; changing browser tabs does not change the source. A compact picker to the left of the centered playback controls shows the selected favicon, roughly three quarters of a second favicon fading out, and a dropdown chevron. Its capsule hover profile and semantic foreground states match the playback buttons. The button favicons are grayscale at rest and return to their original colors on hover or press, using the shared hover animation and Reduce Motion behavior. Dropdown rows retain their full-color favicons. [MediaSourceMenu.swift](../Sources/Browse/MediaSourceMenu.swift) builds native menu rows with 16-point favicons, a fallback music icon, and a checkmark for the selected source. On macOS 27 and later it explicitly requests visible images because automatic menu image visibility can suppress them. The dropdown and favicon preview order sources by most recent playback start or explicit selection; metadata updates and background refreshes preserve that order. [[tests#Media source menu images]] checks native image visibility and selection routing. At very narrow sidebar widths it moves to its own row to keep controls separate; choosing a source selects its browser tab and focuses its pane without changing playback. The close button dismisses the whole panel, retaining all sources and leaving playback unchanged. Refreshes, metadata changes, and already-playing sources cannot reveal a replacement card. A new playback start reopens the panel with all current sources still available. Clicking the title reveals its owning pane. Live pane transfers move ownership to the destination window while retaining the same player. Command failure offers a return to the page rather than claiming success. Volume remains controlled by the page; Bend does not expose a volume button or send volume commands.

[[tests#Media progress layout]], [[tests#Media slider interaction]], [[tests#Media playback progress]], [[tests#Media session commands and metadata]], [[tests#Media frame routing and lifecycle]], [[tests#HTML media fallback controls]], [[tests#Sidebar media ownership]], and [[tests#Media source selection]] exercise the bridge and ownership boundaries with local WebKit fixtures. [[tests#Live media session smoke test]] provides an opt-in check against a real player. Commands time out after five seconds; frame refreshes time out after two seconds. Closing a pane or navigating to a native Bend page detaches its observer and pauses its media. An inactive media report retains its source and last metadata for up to two seconds to cover track replacement, with commands disabled and progress frozen. Resumed state cancels expiry; navigation, frame departure, controller reset, and invalid frame refresh still remove the source immediately. [[tests#Media track transitions]] covers selection stability and cleanup.

## Exclusive media playback

[MediaPlaybackFocus.swift](../Sources/Browse/MediaPlaybackFocus.swift) gives newly started playback priority and pauses media in other panes, including background tabs and other Bend windows.

Browser stores share their root store's playback coordinator. It retains controllers weakly, so live pane transfers keep their registration and do not count as a new playback start. A playing transition claims ownership, clears any old explicit card selection in that window, and pauses competing panes through their standard pause handlers and known HTML media elements. Native WebKit pause is the fallback for players without usable handlers. Pausing or closing the winner does not resume an older player automatically.

Native ownership revisions invalidate queued work after a newer start. Each frame also reports a playback revision; a delayed pause checks that revision and its document/player identity inside JavaScript before acting. [[tests#Exclusive media playback]] covers handoff within and between windows and rejection of an obsolete pause. [[tests#HTML media fallback controls]] verifies interruption pauses the actual audio element.

## Sidebar sizing

[SidebarResizing.swift](../Sources/Browse/SidebarResizing.swift) supplies an invisible eight-point handle at the sidebar's right edge, with a horizontal resize cursor and immediate resizing between 200 and 400 points.

Dragging measures pointer movement in window coordinates so resizing the sidebar cannot feed movement back into the gesture. [BrowserStore.swift](../Sources/Browse/BrowserStore.swift) clamps and saves the width in the session. Missing or nonfinite widths default to 250 points; saved widths inside the range remain unchanged and out-of-range values are clamped. Hiding the sidebar preserves its width, and resizing retains live pane controllers.

[BrowserView.swift](../Sources/Browse/BrowserView.swift) animates collapse and restoration over 200 ms with an ease-in-out curve. The sidebar slides and fades at the leading edge while the native pane canvas resizes in place, retaining its WebViews and document state. Rapid toggles reverse toward the latest layout. Reduce Motion disables the animation; width dragging remains immediate. [[tests#Sidebar visibility animation]] covers intermediate geometry, stable native parents, retained form state, and reversal.

## Floating sidebar

[FloatingSidebar.swift](../Sources/Browse/FloatingSidebar.swift) reveals the hidden sidebar at the left window edge without resizing the browser canvas or changing the pinned-sidebar preference.

In the key window, moving within thirteen points of the left edge reveals a rounded panel using the saved sidebar width and window material. It extends to a six-point top inset in both windowed and fullscreen modes, covering the browser pane and its titlebar beneath the native traffic lights. Its compact header reserves traffic-light space and aligns its pin and download controls with their centerline. The panel slides and fades in from the left over 180 ms; Reduce Motion makes the transition immediate. The existing tab list supports selection, closing, and new tabs; its sidebar toggle pins it open. Hovering the panel or its small edge gap keeps it visible. Leaving for 180 ms dismisses it; reentry cancels dismissal. Window deactivation also dismisses it. Hover state is transient and independent per window.

[BrowserView.swift](../Sources/Browse/BrowserView.swift) overlays the panel above the unchanged mounted canvas. [BrowseWindow.swift](../Sources/Browse/BrowseWindow.swift) routes panel presses directly to AppKit so underlying pane and window drag regions cannot capture them. [[tests#Floating sidebar interaction]] covers native hit testing, selection, hover lifetime, and preserved canvas geometry.

## Sidebar tab reordering

[TabReordering.swift](../Sources/Browse/TabReordering.swift) uses native sidebar drags to reorder or join tabs, with distinct insertion-line and whole-row previews.

A native mouse handle covers the tab label and starts dragging after five points of movement; ordinary clicks still select the tab, and close controls remain separate. A window-level surface shows a title badge and insertion line using the sidebar rows’ actual bounds. The middle 60% of a visible row joins tabs and shows a whole-row highlight plus a “Join tabs” badge. The top and bottom 20% select reorder boundaries; blank sidebar space after the last row remains an end-of-list target. Escape, window deactivation, source removal, or release outside all valid targets cancels without merging or changing order. The drag surface ignores hit testing, and retiring a SwiftUI handle explicitly clears its tracking and overlay. A fresh mouse-down cancels any unfinished gesture before reaching the newly clicked control. The event monitor forwards mouse-up to AppKit so repeated drags work. A completed move animates for 180 ms unless Reduce Motion is enabled.

Hovering a row’s join area for 400 ms selects the destination tab and clears zoom, retaining the original dragged tab. Moving into its visible canvas previews a merge above, below, left, or right of a chosen pane, using the same half-pane geometry as pane dragging. The whole source split tree occupies that half. Leaving the row cancels its pending timer; leaving a pane clears its preview. Cancellation after preview leaves the destination selected, matching pane dragging. Already-visible destination panes can be targeted directly; hidden panes, source-tab panes, zoomed canvas targets, stale sources, and unrelated windows are rejected.

[BrowserStore.swift](../Sources/Browse/BrowserStore.swift) changes only the tab array for reordering and saves its order. Reordering leaves selection, pane layouts, zoom, live page controllers, and closed-item history unchanged. Self-drops, missing tabs, and already-adjacent placements are no-ops. Targets in another Bend window use [[architecture#Cross-window dragging]]; external pasteboard drags cannot reorder tabs. Joining removes the source tab and preserves its entire split tree. A direct sidebar drop places it to the right of the destination tree; a canvas drop replaces only the chosen destination leaf with an equal split along the selected edge, preserving unrelated branches and fractions. Internal split identities and fractions, page IDs, live controllers, and extension identities survive. The destination tab keeps its title, becomes selected, focuses the source’s focused pane, and exits zoom. No closed-item history is created; the combined layout is saved atomically. [[tests#Joining tab layouts]] covers model invariants and restoration. [[architecture#Pane drag and drop|Pane transfers]] use separate tracking and targets.

## Toolbar button styling

[ChromeButtonStyle.swift](../Sources/Browse/ChromeButtonStyle.swift) gives pane controls, find buttons, the media picker, and the extension menu a shared appearance, with semantic foreground levels and subtle circular hover backgrounds shared with the pane title pill.

Pane controls use regular 12-point symbols on a 24-point pitch, with a 22-point hover circle. The title pill and controls are vertically centered in the full 36-point pane header; the loading strip overlays it without shifting the control row upward. The loading strip uses the macOS control accent color. Enabled pane and sidebar icons use the system secondary foreground, becoming primary on hover or press; Increase Contrast also uses primary. Disabled icons use tertiary without an extra opacity multiplier and do not highlight. These hierarchical styles replace fixed RGB colors so system appearance and material foreground treatment remain available. The browser root does not override the inherited foreground with a custom color. Hover reveals a semantic primary background at 6% opacity over 100 ms. Sidebar header controls share the same foreground states, with a larger 14-point symbol and 28-point circle. Reduce Motion removes state-transition animations. The extension menu uses the button menu style so it receives the same sizing and interaction treatment as adjacent buttons. The media picker uses a content-width capsule with the same hover fill and foreground states. Native menu tracking clears cached hover when it begins and ends, preventing a missed mouse-exit event from leaving the extension button highlighted after dismissal.

## Pane navigation controls

Pane buttons in [BrowserView.swift](../Sources/Browse/BrowserView.swift) stay visible for the focused pane and appear together on inactive panes while the pointer is anywhere inside them.

The title precedes Back/Forward, reload/stop, and the extensions/zoom/close group. Twelve-point gaps separate these groups, giving adjacent button centers a 36-point pitch across boundaries versus 24 points within groups. The title has the same minimum gap before the toolbar.

Pane titles use the available width before the fixed-size toolbar, with a single-line trailing ellipsis when necessary. Short titles keep a compact hover pill; long titles have no arbitrary width cap and cannot overlap the controls. The entire toolbar reserves its space when hidden, preventing title movement. Hidden controls neither accept clicks nor appear in accessibility. Visibility fades over 100 ms, or changes immediately with Reduce Motion. Window-level sidebar and download controls remain available independently.

Unavailable history directions and internal start pages disable Back/Forward. Enabled clicks focus their pane and navigate its own WebKit history; [BrowserStore.swift](../Sources/Browse/BrowserStore.swift) observes history availability directly.

Native pane tracking covers web content, headers, and docked developer tools without intercepting input. It clears hover when hidden, removed, or the window deactivates, and refreshes on layout and window activation. Hover callbacks defer SwiftUI state updates until after native layout. [[tests#Pane history controls]] verifies navigation and visibility through the mounted browser shell.

## Sidebar materials

The sidebar and exposed workspace share one native Liquid Glass base on macOS 26 and later. Selected tabs retain their capsule-shaped glass selection. Earlier systems use standard AppKit and SwiftUI materials.

[BrowserWindows.swift](../Sources/Browse/BrowserWindows.swift) hosts each SwiftUI workspace inside [BrowserWindowGlass](../Sources/Browse/GlassAppearance.swift), which observes the persisted window style and tint without replacing its content view. AppKit manages the glass/content geometry together; the transparent window supplies the outer corner clipping. The base spans the sidebar, titlebar area, and gaps around panes, including when the sidebar is hidden. A separate background scrim controls its darkening without dimming foreground content.

[BrowserView.swift](../Sources/Browse/BrowserView.swift) omits the legacy sidebar and canvas backdrops on macOS 26 and later so they do not cover the shared glass. Earlier systems retain behind-window sidebar and under-window materials that follow the window's active state. Selection has no custom fill or border, and pane chrome retains its separate darkened material. Inactive tab hover adds a capsule filled with the shared 6% white button highlight and reveals a close button. Unselected, unhovered tabs omit the close button and reclaim its width and spacing for the title. Hovering or selecting a tab shortens the title to make room for close; leaving an unselected tab restores the extra title space. Titles that exceed their available width fade to transparent over the trailing 24 points instead of showing an ellipsis; fitting titles remain fully visible. Hover fades over 100 ms, or changes immediately with Reduce Motion; selected tabs retain their glass selection.

## Pane materials

Browser panes use rounded native Liquid Glass panels on macOS 26 and later, with standard material on older systems. Focus uses a brighter title plus a configurable transparency, outline, glow, or title tint treatment.

[BrowserView.swift](../Sources/Browse/BrowserView.swift) uses None by default. In Transparency mode, inactive panes, including chrome and page content, receive a configurable black overlay (8% by default). None disables inactive-pane dimming, outlines, glow, and title tint while preserving ordinary pane shadows and the standard title emphasis. Outline and Outline glow instead mark the focused pane without dimming other panes. The outline has a color, independent gap, and thickness. Adjustment ranges are [[Sources/BrowseCore/PaneHighlight.swift#PaneHighlight#outlineGapRange|0–2.5 pt gap]] and [[Sources/BrowseCore/PaneHighlight.swift#PaneHighlight#outlineWidthRange|0.5–2 pt thickness]]. The ring expands outward from the actual pane bounds; changing modes or either dimension never insets the pane or changes its WebView size. It draws beyond the scroll canvas, subject to the window boundary and neighboring pane interiors. Glow centers a colored halo on the focused pane’s silhouette without the ordinary shadow’s vertical offset, with a separate color, 0–100% intensity for shadow opacity, and independent 0–24 pt spread for blur radius. It adds no border stroke or inward glow. Title tint adds a chosen color at 0–100% opacity behind only the active pane’s title-row controls, over its existing material. It works on web, start, and error pages without tinting page content. On web pages it covers the entire shared title-and-find header; inactive headers retain their normal appearance. [[Sources/Browse/PaneShadow.swift#PaneShadowView]] draws both outline and glow on the window decoration layer outside the native pane and canvas clips. Decorations ignore hit testing and accessibility. Title-tint focus changes fade over 100 ms unless Reduce Motion is enabled. [[architecture#UI preferences]] owns these controls.

[BrowserView.swift](../Sources/Browse/BrowserView.swift) places the pane canvas over the shared [[architecture#Sidebar materials|app base material]]. Pane chrome and built-in pages reveal the panel material; web pages keep their own rendering. [PaneShadow.swift](../Sources/Browse/PaneShadow.swift) draws broad, low-opacity black pane shadows on a separate window background layer outside the clipped scroll canvases. The focused pane in Outline glow mode replaces its offset black shadow with the configured centered colored halo; focus and preference changes redraw the layer. It follows visible native pane geometry, including scroll and resize updates, with drawing space sized for the full blur. Outlines are drawn after shadows, and pane interiors are cleared after all decorations are drawn, preserving translucent materials and preventing shadows on neighboring panes. Hidden panes cast no shadow, and the shadow layer ignores input and accessibility. The window shell retains six-point outer margins while page scrolling remains clipped. [[tests#Pane shadow boundaries]] covers drawing beyond a clipped canvas and following moved or hidden panes. Pane content fills its rounded native clip with no additional rim or border inset. Pane body materials retain a 50% black scrim. Headers offer Regular/Clear glass with independent tint and darkening, or an opaque Solid color gradient. Defaults remain Regular, no tint, and 50% darkening. Their background sits beneath the controls; it does not dim text or web pages.

On macOS 26 and later, each live web page extends behind its compact title row. [WebSurfaceHost.swift](../Sources/Browse/WebSurfaceHost.swift) provides one shared background behind the title and any open find controls; opening search extends that surface downward. Glass styles reveal scrolling page colors, while Solid color completely covers them. The combined title and find height sets WebKit's obscured content inset, keeping fixed and sticky site elements below the controls. Start pages, errors, and older macOS versions retain the stacked header layout. Stacked headers and page bodies have separate backgrounds, so header customization does not alter built-in page bodies or apply darkening twice. [[Sources/Browse/BrowserView.swift#PaneBodyBackground]] extends the body glass upward behind the header before clipping it to the body, hiding the body's own top rim so it cannot create a second line below the header. The mini player's controls use the same body background.

Solid headers use [[Sources/Browse/GlassAppearance.swift#SolidHeaderBackground]] for native web headers and [[Sources/Browse/BrowserView.swift#PaneChromeBackground]] for stacked and mini-player headers. Both use the chosen sRGB color with a slight white blend at the top and a slight black blend at the bottom. The fill is opaque and ignores glass tint, darkening, and rim clipping. Native glass is hidden in this mode; controls stay in a stable sibling container, preserving find focus and geometry across material switches. Pane bodies and the window retain their own materials.

Each web view fills its pane's viewport and scrolls its document internally through WebKit. Page content height does not size the web view or the pane. The outer canvas scrolls only when the split layout's minimum dimensions exceed the available window area.

The complete pane, including its outer glass background, header, and page, shares a rounded, layer-backed AppKit container. Clipping is applied after the pane background so its glass compositing layers cannot extend outside the silhouette. The header glass also has rounded top corners, and the clip follows pane resizing. [[Sources/Browse/WebSurfaceHost.swift#PaneHeaderGlass]] and stacked headers in [[Sources/Browse/BrowserView.swift#PaneChromeBackground]] extend the glass beyond the visible header and clip away its reflective rims. Top and bottom clipping follow [[Sources/Browse/BrowserStore.swift#BrowserStore#paneHeaderTopRimClipping]] and [[Sources/Browse/BrowserStore.swift#BrowserStore#paneHeaderBottomRimClipping]]. The live pane's backing material uses the same top clipping so its rim cannot show through the header. Side highlights remain; controls, header height, and WebKit's inset use the visible bounds. Glass headers use the native rim without a custom separator line; Solid color headers have no glass rims.

The web view has an additional native clip around its composited content: all corners under the glass header, or only the bottom corners in the stacked layout. Nested SwiftUI content inherits the pane's environment through its native host.

## Tiling model

[Session.swift](../Sources/BrowseCore/Session.swift) represents pane layouts as binary split trees. Splitting replaces the focused leaf; closing a leaf collapses its parent into the surviving sibling and repairs focus when necessary.

Splits carry an axis and fraction. [BrowserView.swift](../Sources/Browse/BrowserView.swift) draws draggable dividers, constrains pane minimum sizes, and scrolls oversized layouts. Zoom temporarily displays a single pane without modifying the saved split tree.

## Reopening closed panes and tabs

[BrowserStore.swift](../Sources/Browse/BrowserStore.swift) keeps the last fifty pane or tab closures in one in-memory stack. Command-Shift-T reopens the most recent item and selects its original tab and workspace.

[BrowseApp.swift](../Sources/Browse/BrowseApp.swift) exposes Reopen Closed Pane or Tab in the File menu, disabled when the stack is empty. Closing the final pane records one whole-tab closure; extension-requested pane closures use the same history. Reopening clears zoom and the location popup. Closed views are released: restoration uses saved URLs and identities, without recovering page forms, scroll positions, or back-forward lists. Closed-item history is discarded on restart; reopened layouts are saved normally.

[Session.swift](../Sources/BrowseCore/Session.swift) restores the original split tree when the remaining layout is unchanged. Otherwise it inserts the closed pane beside the nearest surviving sibling, retaining subsequent splits, divider changes, and surviving page URLs. If no sibling remains, the pane opens beside the focused pane. Whole tabs return at their saved index. An unused blank tab created automatically after closing a workspace's last tab is removed on reopen; a replacement that has been navigated or split is retained.

## Pane layout animation

[PaneGeometry.swift](../Sources/BrowseCore/PaneGeometry.swift) resolves the split tree into flat pane and divider frames. [BrowserView.swift](../Sources/Browse/BrowserView.swift) keeps pane views keyed by page identity as their positions and sizes change.

Adding a pane animates existing frames over 180 ms with an ease-out curve. The new pane reveals horizontally for a right split or vertically for a lower split, without scaling its text or web content. The scroll view reveals the destination when it would extend beyond the viewport. Reduce Motion disables these layout and insertion animations.

The geometry retains pane minimum sizes and divider constraints, growing the scrollable canvas when necessary. [PaneResizing.swift](../Sources/Browse/PaneResizing.swift) provides native divider views spanning the gaps, with AppKit cursor rectangles and cursor-update tracking for directional resize cursors. Dragging updates immediately using fixed window coordinates, so the moving divider does not feed its own movement back into the resize calculation. Tab switches and session restoration start at their final layout; animation state is not persisted.

## Pane drag and drop

[PaneDragging.swift](../Sources/Browse/PaneDragging.swift) provides title-bar dragging within and between tabs, with a floating title badge and blue previews for placing a pane above, below, left, or right of another pane.

Hovering the title highlights its favicon and text in a compact pill and crossfades the favicon to a four-way drag arrow over 100 ms; Reduce Motion makes the change immediate. Native tracking confines the hover treatment to the title pill. Only the title pill starts an internal pane drag after a movement threshold. Empty header space instead participates in [[architecture#Window dragging]]; toolbar buttons keep their normal actions.

[BrowseWindow.swift](../Sources/Browse/BrowseWindow.swift) owns each gesture before AppKit can start native view tracking. Every press resolves a currently visible handle belonging to the selected tab. The window consumes the complete press/drag/release sequence, including motion after sidebar hover hides the source; pane handles install no event monitors. Its state is idle, tracking a source, or cancelled while awaiting release. Ownership clears before applying a drop. Cancellation keeps consuming the captured gesture through release, so AppKit never receives an orphan release. A fresh press resets ownership before finding its target; closing the window clears it entirely.

The temporary window-level badge and previews ignore hit testing. SwiftUI handle teardown explicitly cancels tracking even if AppKit still keeps the retired view mounted. Teardown, Escape, and window deactivation remove the badge and previews. Pointer positions are compared directly with visible pane rectangles, avoiding AppKit's pasteboard destination routing into WebKit.

[PaneDropEdge.swift](../Sources/BrowseCore/PaneDropEdge.swift) chooses the nearest normalized edge and its half-pane preview across the target's full visible content area. Previews stay visible while the pointer moves within a target. Only target changes clear the old highlight; edge or bounds changes update its path without hiding it. Leaving valid targets, cancelling, or completing a drag clears the preview. Self-drops, stale sources, and unrelated windows are rejected. Pane-edge rearrangement is disabled while zoomed, but sidebar transfers remain available. External pasteboard drags do not initiate pane rearrangement.

Sidebar tab rows highlight during a drag; hovering for 400 ms selects the tab while retaining the original drag source. Newly mounted destination panes become targets immediately. Dropping directly on another tab atomically adds the pane to the right of its focused pane and selects it, including when the source is zoomed; dropping into empty sidebar space detaches it into a new tab at the end of the list. Dropping on the source tab is a no-op with no drop highlight. Successful sidebar transfers exit zoom. Leaving a row or cancelling clears the delayed selection and all previews.

[Session.swift](../Sources/BrowseCore/Session.swift) removes the source leaf, collapses its former split, and inserts the same pane beside the target with an equal split. Unrelated branches retain their identities and fractions. [BrowserStore.swift](../Sources/Browse/BrowserStore.swift) focuses the moved pane and saves the layout without closing pages or adding closed-item history. Same-tab moves retain mounted pane views and WebKit controllers. Cross-tab transfers preserve the page ID, live controller, navigation history, and extension tab identity. An emptied source tab is removed; an emptied workspace receives a blank tab. Transfers create no closed-item history and persist both layouts together. Moves animate over 180 ms unless Reduce Motion is enabled; divider dragging still updates immediately.

## Cross-window dragging

[CrossWindowDragging.swift](../Sources/Browse/CrossWindowDragging.swift) resolves drag destinations across open Bend windows while keeping the pressed window responsible for the mouse gesture.

Pane and tab overlays follow the pointer into the destination window using screen-coordinate conversion. Visible pane edges accept splits; sidebar rows accept joins, and tab insertion bands preserve a whole tab. Empty sidebar space accepts a pane as a new tab. Hover selection uses the destination store. A valid blue pane or sidebar preview brings its destination window to the front without changing the key window, preserving the source’s captured gesture until drop. Unrelated windows, hidden targets, stale sources, and canvas drops into a zoomed pane are excluded. Escape and window deactivation clear previews without transferring ownership.

[BrowserStore.swift](../Sources/Browse/BrowserStore.swift) validates both layouts before moving controllers and rebinding their navigation, focus, link-opening, history, and extension-configuration callbacks. Existing WebViews retain documents, forms, navigation stacks, page zoom, and pinch magnification. Whole-tab moves retain the split tree, tab ID, and dedicated-link pane; moving a single pane repairs its source layout and clears an orphaned dedicated-link role. An emptied source window closes after the destination owns its live pages. The window manifest retains only the surviving windows; cancelling or rejecting a drop never closes its source. Transfers create no closed-history entries and save both sessions. Source membership is published before native views detach; retiring canvas snapshots cannot recreate transferred controllers, and detached hosts stop resizing WebViews now mounted elsewhere.

Extension adapters retain their identity and receive a window-move notification after both models reflect the new ownership. Closing the source window then releases only controllers still owned by it. [[tests#Cross-window live transfers]] and [[tests#Cross-window drag gestures]] cover ownership and native drag routing.

## WebKit integration

[BrowserStore.swift](../Sources/Browse/BrowserStore.swift) retains one WebKit controller per visited pane, keeping live pages and navigation history while switching tabs or changing layouts. The native host uses the system WebKit framework, not an embedded Safari application.

Selecting a visited tab does not load or reload its pages. Its [[architecture#Mounted tab views|mounted view hierarchy]] stays attached while inactive. First visits, reopened closed pages, and process restarts still load URLs.

Website configurations append Safari-compatible product tokens and a Bend identifier to WebKit’s default user agent before navigation, including when leaving extension pages. The Safari version comes from the installed app’s bundle metadata, with a macOS 14-era fallback; this prevents sites such as Google from serving legacy fixed-width layouts. This does not read Safari preferences or share its session.

All panes share the app’s default persistent WebKit website data store, separate from Safari. Navigation updates the stored address and first-pane tab title. Command-clicking an HTTP or HTTPS link opens and focuses a new pane to the right of its source by default, or a new tab when selected in [[architecture#UI preferences]], leaving the source page unchanged and exiting pane zoom. This also applies to links targeting a new window; other new-window web links create tabs. Errors offer retry, and page JavaScript alert, confirm, and text-input dialogs use the origin-labeled [[architecture#JavaScript dialogs|sheet coordinator]].

Command-click routing uses WebKit's navigation-action modifiers and left-button mask in both navigation policy and new-window callbacks. It cancels source navigation when opening the destination; plain clicks and non-link navigation retain their normal behavior.

Pane headers display [[architecture#Page favicons|site favicons]] or a site initial when no usable icon is available. Internal pages retain their app symbols. Same-origin navigation keeps the last successful icon while refreshing it; leaving the origin clears it. Pending work is cancelled so stale results cannot replace the next page's icon.

Custom URL schemes use the confirmed [[architecture#External application links|external-app handoff]]. Website files use [[architecture#Browser downloads]]. Website media permissions, native Safari App Extensions, and Safari session sharing are outside the implemented prototype. Safari Web Extensions use the separate [[architecture#Web extensions|Bend extension host]].

## Browser downloads

[BrowserDownloads.swift](../Sources/Browse/BrowserDownloads.swift) owns native WebKit downloads across all browser windows, with persistent history and a configurable destination that defaults to Downloads.

Settings → UI → Downloads offers a folder chooser and a reset to Downloads. [BrowserStore.swift](../Sources/Browse/BrowserStore.swift) persists the custom path in the shared session preferences. Existing sessions without the preference retain the default. Each transfer captures its destination when added; changing the preference affects new transfers, while active downloads and retries retain their original folder. [[tests#Download destination preferences]] covers persistence, sharing, and destination changes during a transfer.

[PageController](../Sources/Browse/BrowserStore.swift) converts download links, attachment responses, and unsupported MIME types into native downloads. WebKit retains the original navigation request, including cookies and POST bodies; explicit blob and data download links are supported. Downloads retain their native transfer independently of their source tab. Redirects remain limited to HTTP and HTTPS, and authentication uses default system handling.

Tabs created by new-window links (or Command-click configured for a new tab) are removed when their initial main-frame navigation becomes a download, including after redirects. The transfer is retained before its web view is released. Cleanup creates no closed-tab history and restores the previous selection and zoom only if that temporary tab remains selected. A committed document, explicit navigation elsewhere, additional panes, or a moved pane prevents this cleanup. Existing tabs and manually created tabs remain open. [[tests#Download-only tabs]] covers this handoff and focus behavior.

Files first land in private, uniquely named staging directories under their destination folder. Suggested names are reduced to a bounded visible filename without path components, control characters, or directional formatting. An atomic no-replace rename publishes completed files, preserving native download metadata and adding numeric suffixes on collision. Cancelled and failed transfers never publish partial files. Clearing finished entries leaves completed files intact; normal app shutdown cancels active transfers and removes staging files.

The shared manager polls active progress at four updates per second and stops polling when idle. Cancellation keeps WebKit resume data in memory when available. Retry resumes that transfer or restarts an HTTP(S) GET using the originating website data store; it does not replay non-resumable POST requests or expired generated-file URLs. [[architecture#Download database]] retains download records across restarts. Interrupted transfers restore as failed without restarting automatically; HTTP(S) GET retries use WebKit's default website data store after restart.

[DownloadsButton.swift](../Sources/Browse/DownloadsButton.swift) presents filenames, progress, failure details, cancel/retry controls, and Show in Finder in a popover. A circular ring around the arrow shows combined byte-weighted progress for all active transfers. If any transfer's total size is unknown, a rotating arc indicates activity; Reduce Motion keeps that arc stationary. Idle state restores the ordinary circled arrow. [[tests#Combined download progress]] covers aggregation and unknown sizes.

The same shared list is available in every window, including when the sidebar is hidden. Clear Finished removes inactive entries from memory and the database. An empty list hides the button and dismisses its popover unless transfers are still running or a persistence error needs attention. [[tests#Website downloads]], [[tests#Download cancellation and retry]], and [[tests#Download filenames]] cover transfers and file handling with local fixtures.

## Download database

[DownloadDatabase.swift](../Sources/Browse/DownloadDatabase.swift) stores the newest 256 download records in SQLite at Downloads.db beside the root session file, shared by all windows.

Each record has a stable UUID, insertion sequence, and encoded metadata containing its filename, state, byte counts, source URL and method, destination folder, saved file URL, and failure message. Updates retain insertion order. Headers, cookies, POST bodies, embedded URL credentials, generated-file URLs, and native resume data are not persisted. Restored active or cancelling records become interrupted failures. Normal shutdown cancels transfers, removes staging files, and persists that interrupted state.

Lifecycle changes use incremental upserts and deletions in transactions with WAL, full synchronous commits, and secure deletion. Progress polling does not write the database. The manager and database both enforce the 256-record limit, discarding oldest metadata without deleting completed files or cancelling live transfers. Evicted live transfers remain owned until completion and still contribute to the progress ring. [[tests#Download database retention and transactions]] and [[tests#Persistent download history]] cover pruning, rollback, clearing, and restart behavior.

Unreadable or unsupported databases are preserved. A message in the downloads popover offers Retry while new transfers can continue in memory. Retrying a successful read merges retained in-memory downloads with the stored history; failed writes retain the last committed snapshot. [[tests#Download history recovery]] covers preservation and interrupted records.

[FaviconLoader.imageScript](../Sources/Browse/FaviconLoader.swift) loads anonymous-CORS images in an isolated script world. [JavaScriptDialogs](../Sources/Browse/JavaScriptDialogs.swift) presents page-generated alerts, confirmations, and text prompts as native window sheets labeled with the initiating frame's security origin.

## External application links

[ExternalApplicationLinks.swift](../Sources/Browse/ExternalApplicationLinks.swift) lets pages launch installed apps through custom URL schemes after an explicit native confirmation, without app-specific routing rules.

[BrowserStore.swift](../Sources/Browse/BrowserStore.swift) intercepts external schemes in navigation policy and new-window callbacks. Normal links, scripted navigation, iframe launchers, and new-window links all preserve the source document and do not create empty tabs. ## Native input diagnostics

[InputDiagnostics.swift](../Sources/Browse/InputDiagnostics.swift) provides opt-in, bounded native mouse tracing to distinguish window routing failures from events delivered to WebKit.

Settings’ Development tab controls input and pane logging, disabled by default. The preference persists in app defaults and applies immediately to both streams. Startup reads it before session restoration; disabling drains pending writes and stops recording while preserving existing files. Extension diagnostics remain separate.

Two JSONL streams share a run ID, monotonic sequence, timestamps, native view identities, and stable session pane UUIDs:

- `events.jsonl` records each left-button press, drag, and release at application monitoring, window dispatch, AppKit forwarding, web-view entry/return, pane handles, tab drag monitors, and sidebar resizing. The press pane remains the gesture owner through release even after hiding or reparenting; `receiverPaneID` separately identifies the receiving view or current hit target. Non-pane events have a null pane ID and explicit scope.
- `panes.jsonl` records model membership and transfers, pane and tab drag lifetimes/drop targets, hover selection, native attachment/detachment, frame changes, hiding/showing, retained tab root updates, zoom/focus, dividers, and programmatic canvas scrolling. It also records address panels, navigation decisions, command-click handling, web-view replacement/configuration, process exits, JavaScript dialogs, and extension activation, popovers, permission prompts, and focus requests. Tab IDs and related pane IDs identify relationships without conflating tabs with panes. Tab hover selection and canvas merge targets use the same lifecycle stream.

Pane UUIDs are assigned to web views before navigation and preserved across replacement. Native snapshots include window activation, drag ownership, first responder, hit-view ancestry, visibility, gesture-recognizer states, and extension-controller/user-script presence. Instrumentation does not consume or redispatch events; it observes our routing boundaries, not WebKit's internal DOM dispatch.

Both streams live in `~/Library/Application Support/BrowsePrototype/InputDiagnostics/`. Each independently rotates at 500 KiB, retaining a `.previous.jsonl` segment of the same maximum size (four files, at most about 2 MiB total). Oversized segments from older builds are discarded when that stream next writes. Separate serial background queues are capped at 64 pending records each; saturation rejects records without blocking input and reports its count in the next accepted record. Clean termination drains queued writes. Native snapshot identities use process-local hashes without retaining objects or registering weak references, so ancestor inspection remains safe during hosting-view destruction. Native addresses can be reused after destruction; pane UUIDs remain the durable identity. The gesture-owner map uses weak window keys only during live input dispatch. Records exclude coordinates, keyboard input, URLs, titles, and page content.

The hooks span [BrowseApp.swift](../Sources/Browse/BrowseApp.swift), [BrowseWindow.swift](../Sources/Browse/BrowseWindow.swift), [BrowserStore.swift](../Sources/Browse/BrowserStore.swift), [BrowserView.swift](../Sources/Browse/BrowserView.swift), [MountedTabContent.swift](../Sources/Browse/MountedTabContent.swift), [PaneDragging.swift](../Sources/Browse/PaneDragging.swift), [TabReordering.swift](../Sources/Browse/TabReordering.swift), [SidebarResizing.swift](../Sources/Browse/SidebarResizing.swift), [AddressPanelController.swift](../Sources/Browse/AddressPanelController.swift), and the extension bridge. [[tests#Input trace rotation]], [[tests#Independent input and pane log retention]], [[tests#Pane trace correlation]], [[tests#Input diagnostics during hosting teardown]], and [[tests#Input logging preference]] cover retention, attribution, destruction with logging active, and opt-in persistence.

## Web extensions

[ExtensionManager.swift](../Sources/Browse/ExtensionManager.swift) hosts Safari Web Extensions through WebKit's public extension controller on macOS 15.4 and later, with enablement, permissions, and extension storage separate from Safari.

All extension packages, including Safari bundles, are copied into Bend's extension directory before validation and registration. WebKit reads ZIP, XPI, CRX, and unpacked resources. Imports start disabled. The extension list, original import location, declared package identity, approved permissions, and website patterns are saved atomically beside the session data. Each context keeps a stable identifier and extension origin across restarts. Existing externally referenced imports migrate to owned copies while retaining their identifiers and grants; migration failures leave the original record intact.

Manual replacement installs a separate package revision and retains the extension origin and storage. Replacement checks bundle identifiers, declared Gecko identifiers, or manifest keys when present; otherwise it requires the same display name. These checks identify user-selected local packages, not authenticated publisher updates. Invalid or mismatched replacements leave the installed version intact. Additional access keeps an update unloaded until approved. Package folders preserve internal relative symbolic links used by signed frameworks, but reject absolute or escaping links and special files. Removing an extension deletes its managed copy, never its original source.

[[architecture#Native extension messaging]] connects Firefox packages to installed desktop helpers. Safari app-extension handlers remain unsupported: 1Password for Safari's bundle can load, but its native connection, unlock, and autofill do not work. Loading SafariServices does not resolve this failure.

[probe-native-extension.sh](../scripts/probe-native-extension.sh) builds a temporary, windowless diagnostic app that resolves a native extension through the Foundation API used by WebKit. It sends no native messages. The default runs without extra entitlements; setting `BROWSE_PROBE_HOST_ENTITLEMENT=1` signs only the probe with `com.apple.private.can-load-any-content-blocker`. On the tested Mac, PlugInKit rejects the default host for lacking that entitlement, while macOS kills the entitled probe before execution with “No matching profile found.” Bend's build does not claim this entitlement. See the [reproduction and limitations](../docs/extension-support-research.md).

Enabling an extension asks for its requested capabilities and website access. Updated extensions that need additional grants stay unloaded until reviewed. Runtime requests prompt separately and are granted for the current app session. Private website-data access is not granted. Unreadable extension metadata is preserved and prevents writes. Disabling unloads the extension; existing page changes disappear after reload. Removing also deletes the extension's Bend data and managed resource copy, leaving the source app and Safari settings intact.

[ExtensionBrowserBridge.swift](../Sources/Browse/ExtensionBrowserBridge.swift) maps panes from all registered browser stores to extension tabs, with an extension-window adapter for each native browser window. Each window has its own active pane. Tab queries, navigation, activation, closure, and explicit new-tab window requests use the owning store; activation brings that native window forward. Closing a window unregisters only its tabs and adapter. The single shared manager retains installed extensions and their background contexts. The host reports creation, closure, focus, URL, title, and loading changes; tab queries do not instantiate unvisited web views. Web extensions can open web tabs, navigate, reload, activate, or close panes. The windows-create API, tab moves and grouping are not implemented.

[ExtensionDocument.swift](../Sources/Browse/ExtensionDocument.swift) hosts extension-owned pages, including options and extension-created tabs, in separate windows using their required context configuration. These windows and pages participate in the extension window/tab APIs and close when the owning extension is disabled or removed.

Same-tab HTTP(S) navigation retains the document's tab identity and window. Because WebKit confines extension-configured views to their extension origin, the document retains that view and displays an ordinary website view during authentication. Returning through an authorized extension tab update reuses the original extension view and its session storage, preserving onboarding choices. The website view has no compatibility adapter or privileged extension APIs; its host appears in the window title. Websites cannot initiate a privileged return themselves. Links requesting a new window still open separate tabs or extension documents.

[Extension tab updates](../Sources/Browse/ExtensionBrowserBridge.swift) can replace a website with the requesting loaded extension's own page, including a post-authentication confirmation page. [The page controller](../Sources/Browse/BrowserStore.swift) installs a context-configured web view while preserving pane and extension-tab identity. Returning to a website replaces it with an ordinary configuration; native back/forward history resets at this boundary. Saved extension panes wait for extension restoration before loading, and unavailable extensions show an error. Disabling or replacing an extension tears down its pane documents as well as separate windows.

[Navigation policy](../Sources/Browse/BrowserStore.swift) permits embedded pages from loaded extension contexts so inline extension menus can render and communicate with their background. WebKit still enforces web-accessible-resource declarations. Ordinary websites cannot promote themselves into privileged top-level extension documents.

Each browser web view receives the shared extension controller before creation. WebKit provides content scripts, background contexts, storage, and declarative request rules. The pane extension menu invokes actions with a user gesture; WebKit's popup is anchored to the associated visible pane. Availability of individual extension features depends on WebKit's API coverage and any native companion app's requirements.

Importing Chrome or Firefox resources does not establish full compatibility with those browsers. [[architecture#Extension compatibility adapters]] support Firefox 1Password onboarding without modifying its package. The user has confirmed vault items in its toolbar; authenticated inline autofill and desktop integration remain unverified.

## Native extension messaging

[ExtensionNativeMessaging.swift](../Sources/Browse/ExtensionNativeMessaging.swift) bridges WebKit native-message delegates to Firefox-compatible desktop helpers without sharing Safari's extension state.

The host resolves user then system Mozilla NativeMessagingHosts manifests, validates names, stdio transport, executable paths, and the requesting Gecko ID against allowed_extensions. Only loaded, registered contexts with nativeMessaging permission can connect. Launch arguments contain the real manifest path and extension ID; Bend remains the parent application with its own signature.

Persistent ports and one-shot replies use length-prefixed UTF-8 JSON over pipes. Frames are limited to 1 MiB, queued writes to 4 MiB, and concurrent connections to sixteen per context. Reads handle fragmented frames without waiting for the pipe to fill. Invalid input, EOF, write failures, and one-shot timeouts close the session. Payloads and helper stderr are not logged. Disable, removal, replacement, port disconnection, and permission revocation tear down connections and terminate helpers.

The installed 1Password helper is discovered through its Firefox manifest. Desktop unlock requires a qualifying distribution signature and the Bend app to be added through 1Password Settings → Browser → Add Browser, plus desktop integration enabled in the extension. Bend does not alter the trusted-browser list or impersonate Firefox. The transport and real extension's connection request are tested. The helper rejects Apple Development signing; the Developer ID build installed in Applications has user-confirmed desktop integration and Touch ID unlocking. See [[architecture#1Password connection probe]] for the standalone diagnostic limitation. Safari's proprietary app-extension route is not implemented.

## Extension compatibility adapters

[ExtensionCompatibility.swift](../Sources/Browse/ExtensionCompatibility.swift) adds notifications, limited privacy settings, and main-frame navigation-target events while preserving WebKit's native event delivery and permission checks.

The controller's extension-only web-view configuration injects the adapter at document start. The native `browser` namespace remains intact so WebKit can dispatch events; the `chrome` namespace forwards native APIs and supplies missing ones. Notification and privacy namespaces are also exposed on `browser`. Ordinary website views receive no adapter, and native message handling rejects non-main frames, foreign origins, unloaded contexts, and missing operation-specific permission. Extension source packages are not patched.

The privacy adapter implements password saving and legacy/address/card autofill service settings using [ChromeSetting's API shape](https://developer.chrome.com/docs/extensions/reference/api/types). Bend has no built-in savers, so reads report false and not controllable, disabling and clearing succeed without changing preferences, and enabling is rejected. Promise and callback forms are supported, with callback errors scoped to `runtime.lastError`; unrelated privacy settings and private scopes are unsupported. Safari preferences are never changed. This prevents Firefox 1Password's saved-account startup path from throwing on its browser password-manager settings calls.

[ExtensionManager.swift](../Sources/Browse/ExtensionManager.swift) includes the declared privacy permission in approval and persisted grants because WebKit omits unsupported permissions from its requested-permission set. The adapter checks explicit grants, including expiry and revocation, rather than WebKit's unsupported-permission query. Existing installations without that grant require review before loading with the new capability.

[ExtensionNotifications.swift](../Sources/Browse/ExtensionNotifications.swift) delivers basic macOS notifications, requests system authorization when a notification is created, and returns authorization failures to the extension. Notification IDs are scoped to the owning extension. Create, update, clear, enumeration, click, button, and dismissal callbacks are supported for the current session. Up to two buttons and bounded title/message lengths are accepted; richer notification types are rejected. Notifications use Bend's system icon and identify the extension in their title. Disabling, uninstalling, or replacing a context clears its tracked notifications and page registrations. Permission-level changes are checked on visibility changes and periodically while extension pages are alive.

[BrowserStore.swift](../Sources/Browse/BrowserStore.swift) records opener relationships for main-frame link openings before publishing the destination tab. [ExtensionBrowserBridge.swift](../Sources/Browse/ExtensionBrowserBridge.swift) exposes those relationships through WebKit. The adapter derives `chrome.webNavigation.onCreatedNavigationTarget` from real tab-created events, checking the current navigation permission and URL filters. Unrelated tab creation does not emit this event. Subframe source IDs are unavailable through this host's public navigation interface, so subframe openings are excluded rather than mislabeled. The native `browser.webNavigation` namespace is unchanged.

The [compatibility regression tests](../Tests/BrowseTests/ExtensionCompatibilityTests.swift) exercise native messaging alongside the adapter, notification scoping and revocation, rejection of website callers, cleanup, and navigation-event identity. The opt-in real-package test follows Firefox 1Password onboarding without entering credentials.

## Browsing history

[History.swift](../Sources/BrowseCore/History.swift) models a bounded, serializable collection of web visits. It normalizes HTTP and HTTPS addresses, strips embedded credentials, and combines rapid consecutive visits to the same URL.

Visits retain titles and timestamps, newest first, up to 10,000 visits. Consecutive visits to the same URL within 30 seconds coalesce. Removing a URL also removes its learned suggestion choices; clearing history removes both visits and choices.

[BrowserStore.swift](../Sources/Browse/BrowserStore.swift) records successful web navigations. Later URL changes on a completed, idle page create visits, while title changes update the latest matching visit. Internal pages and failed navigations are excluded.

[BrowserStore.swift](../Sources/Browse/BrowserStore.swift) persists visits and learned choices through [[architecture#History database]] shared across windows. Secondary stores forward history writes and observations to the root owner, avoiding conflicting snapshots. Writes are debounced and flushed with session saves; removal and clearing save immediately. Unreadable history storage is preserved until an explicit clear permits replacement, with errors exposed by the store.

## History database

[HistoryDatabase.swift](../Sources/BrowseCore/HistoryDatabase.swift) uses macOS’s system SQLite library for Bend’s own `History.db`, separating URL records, individual visits, and learned address-bar choices.

The database lives under `Application Support/BrowsePrototype`, alongside the primary session. It follows Safari’s URL/visit organization, without reading Safari’s database or depending on its private schema. Visit UUIDs and titles remain per visit; timestamps use seconds since January 1, 2001. Foreign keys link visits and choices to unique URLs. Time and URL indexes support lookup and cleanup.

One root store owns the connection and cached snapshot. Saves apply only changed rows inside a transaction; deleted visits and choices are removed and unreferenced URLs collected. SQLite uses WAL, full synchronous commits, and secure deletion. The in-memory 10,000-visit bound and existing suggestion ranking remain unchanged. Website data stays in WebKit’s separate store.

On first initialization, valid `history.json` visits and choices import in the same transaction as the schema version. JSON is removed only after the database loads successfully; a leftover JSON file is never reimported into an initialized database. Corrupt JSON, corrupt databases, and unsupported schema versions block ordinary persistence. Explicit Clear History may discard unreadable storage and initialize an empty database. Transaction failures leave the previous snapshot intact and pending changes available for retry.

## History interface

[HistoryView.swift](../Sources/Browse/HistoryView.swift) displays searchable visits grouped by local calendar day in the built-in history page, with controls to revisit or remove pages and clear recorded history.

The History menu and Command-Y open `browse://history`, reusing an existing history pane across workspaces when available. Selecting a visit navigates the current pane; its context menu can open a new tab. Removing a page deletes all visits and learned choices for that URL. Clearing all history requires confirmation and leaves open pages and website data intact. The view displays history read and write errors from the store.

## History suggestions

[History.swift](../Sources/BrowseCore/History.swift) groups visits by URL and ranks matching suggestions using prior choices, URL match strength, and visit frequency weighted by recency.

Matching ignores case and diacritics and requires every query word to occur in the title or decoded URL. URL-prefix completions preserve the typed prefix; whitespace-containing queries do not receive inline completions. Bare-host queries can omit a leading www. for both inline completion and home-page ranking. Explicit www. and scheme prefixes retain literal matching, and selecting the suggestion still navigates to its original recorded URL.

Suggestions combine visits into one result per URL. Ranking prefers URL match strength, with visited home pages ahead of deep links for host-prefix queries, then frequency with a 30-day recency half-life plus a bounded learned-choice bonus. A single previous choice cannot permanently outrank repeated visits; path queries still find matching deep links. Learned choices are bounded to 1,000 query/URL pairs and decay over time. Matching runs locally without sending partial queries to a search engine or preloading pages.

The interaction draws on [Firefox's address-bar matching](https://support.mozilla.org/en-US/kb/address-bar-autocomplete-firefox), its [frequency/recency and adaptive-input ranking](https://firefox-source-docs.mozilla.org/browser/urlbar/ranking.html), and [Safari's combined search field](https://support.apple.com/en-ie/guide/safari/sfrid73436cb/mac). Bend implements its own bounded ranking over recorded visits.

[AddressPanelController.swift](../Sources/Browse/AddressPanelController.swift) combines history matches with a direct visit or search action in the [[architecture#Location popup]]. The popup refreshes when history changes; selecting a history result records the typed query to influence later rankings.

## Address handling

[Session.swift](../Sources/BrowseCore/Session.swift) resolves web addresses, localhost development URLs, built-in start pages, and search queries. Explicit non-web schemes are rejected; search text is encoded as a Google query parameter.

Bare hostnames containing dots use HTTPS, while localhost and loopback IPv4 addresses use HTTP. [BrowserStore.swift](../Sources/Browse/BrowserStore.swift) also limits WebKit navigation to web URLs and internal blank documents.

## Location popup

[AddressPanelController.swift](../Sources/Browse/AddressPanelController.swift) owns a floating command-palette-style location panel. A rounded search field, compact history rows, and a shortcut footer sit within a frosted shell. URL entry remains separate from pane chrome.

Command-L opens the popup for the focused pane, with its current URL selected (blank for start pages). Return navigates that pane using the [[architecture#Address handling|address resolver]]; invalid input stays open with an error that clears when editing resumes.

[AddressPanelController.swift](../Sources/Browse/AddressPanelController.swift) displays [[architecture#History suggestions]] beneath the input. Arrow keys select results, Return opens the selection, and clicking a result opens it. Eligible URL prefixes autocomplete with the added suffix selected; deletion, marked text input, and edits away from the end suppress autofill.

Opening the popup shows frequent/recent pages while retaining the current address selected for editing. Typing shows up to six history matches alongside an explicit visit/search action. Inline URL matches become the selected top result; other queries keep the explicit action selected. History updates preserve selection when possible. Each history row has a Remove from history button that deletes all visits and learned choices for its URL, saves immediately, and removes stale suggestions without navigating or closing the popup. Results sit directly beneath the input with compact spacing; validation errors reserve extra space only while visible.

The popup is a borderless child panel centered horizontally on its target pane's visible native bounds, including start pages. On opening, its top edge sits one-fifth down the pane. That top position stays fixed relative to the window's top for the entire presentation: result counts, validation messages, pane resizing, scrolling, and delayed mounting cannot shift the input vertically. Reopening or targeting another pane establishes a new top position. Its width adapts to the pane, with a readable minimum; long results scroll within the space below the anchored top. Until a pane is mounted, browser content bounds supply the initial fallback position. [[tests#Pane-centered location popup]] covers pane targeting, fixed-top resizing, validation errors, partial visibility, and delayed mounting. It uses native popover material with a darkening scrim and a subtle outer rim, accepts keyboard focus without becoming the main window, supports full-screen use, and hides when the app deactivates. A smaller search field includes a magnifying glass and a light-gray placeholder. The footer shows arrow-key navigation, Escape dismissal, and Return submission hints beneath a faint separator.

A stretchable rounded material mask shapes both the backdrop and the native window shadow. The dark scrim uses the same corner radius, keeping it inside the material's outline as the popup width changes.

Selected suggestions use a rounded blue background with white titles and lighter secondary text, icons, and history-removal buttons. Two-line rows retain both page titles and URLs. Selection leaves keyboard focus in the address input; the panel remains horizontally centered and resizes downward from its fixed top edge.

Escape dismisses an existing tab’s popup and returns keyboard focus to the browser, as does successful submission. During a new blank tab or split pane’s initial address entry, Escape or Command-W discards both the popup and the new item and adds nothing to closed-item history. Canceling a split removes it from the layout and restores the previous pane focus and zoom; canceling a tab restores the preceding tab and zoom. Typed but unsubmitted text still counts as initial entry. Successful submission or outside dismissal commits the pane or tab; opening its popup again does not make it disposable. Existing panes, link-created panes, new-window initial tabs, and last-tab replacements are retained. [[tests#Canceling new tab entry]] and [[tests#New tab popup keyboard cancellation]] cover the boundaries. Losing key-window status dismisses it without reclaiming focus, allowing outside clicks to select another pane or application normally.

[BrowserStore.swift](../Sources/Browse/BrowserStore.swift) requests the popup after creating blank split panes, tabs, or a replacement for the last closed tab. Link-created panes and tabs already have a destination and do not prompt. Popup requests validate pane identity; submitting after the target has closed or left the selected tab cannot navigate another pane.

[BrowserWindows.swift](../Sources/Browse/BrowserWindows.swift) connects each store's location-request callback to the panel controller. Requests carry a pane identity after the store has updated selection and focus, so presentation does not depend on a newly created SwiftUI pane observing an earlier event.

## Link hover preview

Hovering a link shows its destination in a compact, noninteractive bubble at the bottom of that browser pane, moving away from the cursor.

[LinkHoverPreview.swift](../Sources/Browse/LinkHoverPreview.swift) observes link targets in an isolated WebKit content world, including subframes and nested elements in open shadow roots. Relative destinations resolve against the document base URL. Encoded URLs retain their full scheme, with control and directional formatting characters removed; long destinations truncate in the middle to fit the pane.

[WebSurfaceHost.swift](../Sources/Browse/WebSurfaceHost.swift) places the preview above page content without intercepting clicks. It prefers the bottom-left corner, switches to the right when the cursor approaches, and returns left once clear. Native pointer tracking updates placement even within the same link; layout also recomputes it after resizing. When a long URL would overlap the cursor at both corners, it truncates into the roomier side with a gap around the pointer. Leaving the pane, hiding it, scrolling, clicking, or navigating clears the preview. [FocusWebView](../Sources/Browse/BrowserStore.swift) clears hover state when reattached, preserving pane-local behavior across live transfers. Shared content controllers route hover messages to their originating web view rather than retaining a pane or page controller.

## Window dragging

Empty sidebar and pane-header areas move the browser window, while tab rows, title pills, resize handles, and controls keep their dedicated interactions.

[WindowDragging.swift](../Sources/Browse/WindowDragging.swift) supplies native mouse targets for empty sidebar and pane-header regions, with explicit control exclusions. Background presses pass through AppKit's normal window event dispatch before the target's mouse-down handler requests native dragging, preserving window activation, shadow, and glass appearance. [BrowseWindow.swift](../Sources/Browse/BrowseWindow.swift) exposes the native mouse-down dispatch scope for hit testing; it does not start background window drags itself. The sidebar target overlays its scroll view but claims only mouse-down, leaving scrolling, hover, and other events to the underlying content. Pane title handles retain their dedicated routing. Traffic lights, sidebar tab rows, pane toolbar buttons, sidebar buttons, and the resize edge are excluded. Empty pane-header presses also focus that pane. Hidden and clipped regions cannot initiate dragging.
