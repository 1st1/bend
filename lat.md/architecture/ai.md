# Native AI chat

Native chat works with all website panes in one tab through Vercel AI Gateway, using the owned [[Sources/AI]] module. See [[lat.md/tests/ai-tests|AI tests]].

## Tab conversations

[[Sources/Browse/TabChat.swift#TabChat]] owns a tab's active conversation, streamed bubbles, model selection, and cancellable agent run.

The Chat command in [[Sources/Browse/BrowseApp.swift#AppDelegate#popupCommands]] opens [[Sources/Browse/ChatSidebar.swift#ChatSidebar]] opposite the configured tab sidebar, including when that sidebar is hidden. Changing sidebar position moves chat to the other edge while retaining its conversation. Input focus is assigned immediately on opening, independently of credential restoration. A loaded account model catalog is reused across sidebar openings. Its transparent background exposes the shared [[lat.md/architecture/sidebar#Sidebar materials|window glass]], matching the tab sidebar. The transcript is clipped below the unadorned fixed header and scrolls beneath the translucent composer. [[Sources/Browse/ChatSidebar.swift#ChatHeader]] uses shared sidebar sizing and alignment. Native controls are positioned above the unified toolbar, which otherwise intercepts clicks and hover in the titlebar strip; SwiftUI anchors own their lifetime, while the controls are pinned to the chat panel’s trailing edge and shared header centerline across resizing and sidebar transitions. The window routes header mouse presses and releases to these controls before AppKit can consume them as toolbar events. The transcript also bounds hit testing to its viewport. The header omits the Chat title and sparkles, offering labelled Clear chat and Close chat controls on the shared centerline. It has no bottom divider and an empty transcript shows no introductory text. The floating composer uses [[Sources/Browse/FloatingPanelBackground.swift#FloatingPanelGlassView|configurable Liquid Glass]] with rounded corners, defaulting to regular frosted glass and a 45% black background scrim. Its outer and bottom insets match the pane gap; the adjacent canvas supplies the inner gap on either side; the searchable model selector sits below the input on the left, opposite Send/Stop. [[Sources/Browse/BrowserView.swift#BrowserView]] shrinks the retained pane canvas to make room without rebuilding WebViews. Closing the sidebar retains its conversation and an active run; switching tabs selects that tab's independent chat. Clear chat starts a fresh conversation while retaining the previous one in saved history. Closing a tab or window cancels its runs and saves its messages. Duplicated tabs start without conversations. [[lat.md/architecture/ai#Saved chat history]] restores messages and panel visibility across restarts. Private windows disable the Chat command and reject sidebar creation, model requests, pane metadata access, tools, and citation navigation before any AI diagnostics are emitted.

Agent calls use the AI module's streaming agent loop with serial tools and bounded model steps. Successful turns retain tool history for follow-ups. [[Sources/AI/Agent.swift#Agent#run]] normalizes blank arguments to an empty JSON object only for explicitly parameterless tools after a complete response; normalized history is sent on subsequent turns. Malformed JSON and missing required inputs remain tool errors. Cancellation and errors preserve partial visible text and append an interruption marker without dangling or replayed tool calls. Disconnecting Gateway cancels active chats. Provider errors are summarized without exposing raw response bodies or credentials.

## Gateway connection

[[Sources/Browse/AISettings.swift#AISettings]] shares Gateway connection state across windows. Settings → AI offers one connection picker for OpenAI login, OpenAI API key, Anthropic API key, or Vercel Gateway API key. Only the selected method’s controls are shown.

[[Sources/Browse/AISettings.swift#GatewayCredential]] uses the current build profile's Keychain service, keeping debug credentials separate from production. The key is loaded lazily off the UI thread when AI UI opens, never stored in session JSON or defaults. Disconnect removes it. Gateway HTTP uses ephemeral sessions without cookies, credential storage, or redirects. The model catalog is fetched live, restricted to tool-capable language models excluding batch variants. The preferred model persists in profile preferences and initializes new chats; a chat-specific selection does not change that preference. New chat resets to the preferred model. Catalog refresh preserves an explicit preference. [[Sources/Browse/AIModelPicker.swift#AIModelPicker]] supplies a searchable popover in Settings and the composer, matching model names and IDs.

Settings → AI exposes the full [[Sources/Browse/AISettings.swift#AISettings#defaultSystemPrompt|default system prompt]] in an editable text area. The default identifies the assistant as part of Bend, a native macOS browser based on Apple’s WebKit engine. Edits persist in profile preferences and apply to the next message in any chat, while a running turn retains its original prompt. Reset to Default appears only for changed text and removes the stored override. [[Sources/Browse/TabChat.swift#TabChat#send]] supplies one system template per run, separate from retained conversation history. The `${panes}` placeholder is expanded by the pane-context provider in [[Sources/Browse/TabChat.swift]] before every model request, including tool follow-ups. It contains only this tab’s live pane IDs, titles, URLs, citation URLs and active-pane flag, labelled as untrusted metadata. If a custom prompt omits the placeholder, context is appended. Pane listing requires no model tool call.

Authentication supports OpenAI account sign-in and separate OpenAI, Anthropic, and Gateway API keys. Direct keys are validated against the provider’s model catalog before saving into separate profile-scoped Keychain services; Gateway keys use its credits endpoint. Switching connections cancels active runs and resets the model catalog. Direct OpenAI uses Responses with bearer authentication; direct Anthropic uses Messages with its API-key header and paginated model discovery. API usage is billed separately from chat subscriptions. Vercel OAuth plumbing remains internal and is not offered by the connection picker. Messages and requested page content go directly to the selected provider, or through Gateway when selected. Connection failures remain visible and retryable. Authentication and model discovery do not generate billable completions. Test connection sends a small, bounded inference request to the preferred model, with no panes, conversation history, tools, or search. It shows a sanitized success or failure, times out after 30 seconds, and clears/cancels when the connection or preferred model changes.

## Pane tools

[[Sources/Browse/TabChat.swift#PaneChatTools]] exposes pane creation, bounded main-frame reading, navigation, clicking, and filling through a fixed tab identity and live pane membership checks.

Settings → AI lists every tool with an independent switch. [[Sources/Browse/AISettings.swift#AISettings#setToolEnabled]] persists disabled tools in profile preferences. Disabled tools are omitted from new runs and checked again at execution time, including calls already advertised by a running agent. All tools default on; all may be disabled. The former list_panes tool is replaced by live system-prompt context. Each request also lists the tools actually disabled in Settings; the default prompt distinguishes disabled tools from unsupported capabilities.

Tools cannot access another tab's panes, native browser pages, files, or extension documents. Navigation and pane creation accept HTTP(S) URLs without embedded credentials. Page reads return bounded text and element selectors without form values or editable drafts, including text inherited by ancestor labels; they do not inspect frames or images. Click and fill accept only a unique selector generated by the current read snapshot and still bound to its original element. Arbitrary attribute selectors are rejected before DOM lookup so tool errors cannot probe sensitive field values. Fill rejects password, payment, and token fields. It does not explicitly submit, but website input/change handlers may submit or perform other actions, so filling requires approval too. JavaScript arguments are passed separately in WebKit's isolated client world. Tools check cancellation before work and membership again after asynchronous reads.

Reads paginate a stable snapshot with up to 24,000 Unicode code points, 100 interactive elements, and 100 citation references per chunk. The optional cursor advances through the snapshot; has_more and next_cursor report continuation. Starting without a cursor replaces the snapshot. Navigation or a replaced snapshot invalidates old cursors. Snapshots live in WebKit’s isolated client world and do not scroll the page. Chunks explicitly distinguish remaining metadata from page text. Expanded tool results are labelled as previews when capped at 12,000 characters; the model receives the complete chunk. The tool description and default prompt instruct the agent to continue through relevant chunks before summarizing.

The agent is instructed to treat page content as untrusted and act only on user requests. Inline [[lat.md/architecture/ai#Action approval]] enforces confirmation for every pane creation, navigation, click, and fill independently of those instructions. Tools operate on the current live page, so the model must re-read after navigation or interaction. A loading page returns a recoverable tool error.

The create_pane tool in [[Sources/Browse/TabChat.swift#PaneChatTools#execute]] opens the requested URL to the right of an existing pane after inline approval, preserving that page. It revalidates the source and live permission, starts loading the new pane, and returns its ID, URL, and citation. It stays within the chat’s tab and does not claim a designated link pane or create a WebKit opener relationship. Fresh pane context includes the new destination on the next model request.

## Action approval

[[Sources/Browse/AIActionApproval.swift#AIActionApproval]] suspends each proposed pane creation, navigation, click, or fill until the user presses its action button inside the chat. Model output cannot approve a request.

[[Sources/Browse/ChatSidebar.swift#ChatActivityRow]] expands the pending tool card with its current page, destination or observed target, selector, and proposed text. Open in new pane, Open page, Click element, and Fill field approve exactly the displayed request; Skip declines it. No modal dialog or keyboard default grants approval. The controls remain outside the card's bounded scrolling detail area.

[[Sources/Browse/TabChat.swift#TabChat#approveAction]] accepts approval only from the active tab's open chat during its live run. Each pending request has a fresh ID; duplicate clicks and callbacks from an older request cannot release another action. Stopping a run, closing its tab/window, clearing history, or switching accounts cancels pending approval. Hiding chat or switching tabs leaves the action waiting for the user to return. Pending continuations are never persisted or restored from saved conversations.

[[Sources/Browse/TabChat.swift#PaneChatTools#execute]] rechecks tool permission, tab membership, controller identity, URL, and navigation revision after approval; reloads invalidate approval even at the same URL. Clicks and fills also bind approval to the observed live DOM element and its markup in WebKit's isolated client world. Navigation and text arguments remain bounded. Tools without a chat approval handler reject actions by default. Native start pages can request navigation without needing a mounted WebView for the approval controls.

Approval authorizes the website's resulting behavior, including script handlers; it cannot guarantee that an approved click or fill is harmless. Provider-hosted web search executes remotely and is outside this local approval path. Page content remains untrusted, and the selected provider receives requested page content and conversation context.

## Chat composer

[[Sources/Browse/ChatComposerInput.swift#ChatComposerInput]] provides a native multiline editor. Enter and Shift-Enter insert a newline at the selection; Command-Enter sends through the same chat action as the Send button.

The editor grows from two to seven lines and then scrolls internally. It preserves native selection, editing, and input-method composition. Command-Enter is consumed without sending when the Send button would be disabled or an input-method composition is active. [[Sources/Browse/ChatSidebar.swift#ChatSidebar]] shares the Send button's availability with the editor and keeps Stop available during a run, including while an action awaits approval.

Up from an empty input recalls this conversation’s last sent prompt with its full text selected. Up and Down browse older/newer prompts while that selection remains intact; Down past the newest returns to an empty input. Editing or moving the cursor returns arrow keys to native text navigation. Escape clears an intact recalled prompt first. Otherwise [[Sources/Browse/BrowseWindow.swift#BrowseWindow#sendEvent]] stops the active tab’s visible chat run, including pending approvals, while respecting input-method composition, sheets, and pane dragging.

[[Sources/Browse/ChatComposerInput.swift#ChatComposerTextView]] recalls and clears prompts through native text insertion, preserving the editor’s typing attributes, change notifications, and layout. Recalled text has the same font, color, line spacing, and component height as normal input with the same contents, followed by Select All.

## Markdown messages

[[Sources/Browse/ChatMarkdown.swift#ChatMarkdown]] renders assistant responses as native selectable Markdown while user messages remain literal text.

[[Sources/Browse/ChatSidebar.swift#ChatSidebar]] right-aligns user bubbles, left-aligns assistant bubbles, and caps both message widths, including padding, at 90% of the transcript’s usable width. Short messages retain their natural bubble width; the cap follows chat-panel resizing. The AI chat bubbles group at the bottom of Settings → UI offers a continuous Bubble transparency slider, backed by [[Sources/Browse/BrowserStore.swift#BrowserStore#aiBubbleTransparency]]. It adjusts both accent-colored user and dark-grey assistant text-bubble backgrounds, from opaque at 0% to absent at 100%. The default gives a subtle fill; text, tool cards, and layout retain their existing appearance. The shared session preference updates open chats immediately and persists across restarts.

Swift Markdown parses each streamed response into headings, paragraphs, nested ordered and unordered lists, task lists, quotes, thematic breaks, code blocks, and tables. Each response uses one attributed NSTextView so selection and copying span all paragraphs and blocks. Code wraps within the bubble and table cells use tab-separated columns. Streaming updates preserve the selected range. Inline emphasis, strong text, strikethrough, code, and HTTP(S) or mail links retain their formatting. Raw HTML is displayed literally and images use descriptive text without fetching remote content. Incomplete streamed link destinations are withheld while the readable label appears progressively, so pane UUIDs and encoded URLs never flash as ordinary text. Complete links retain their routing targets. Native text updates replace only the changed attributed suffix, preserving the unchanged prefix and selection instead of resetting the entire text storage. Code spans/fences remain literal.

## Page citations

[[Sources/Browse/ChatPageLinks.swift#ChatPageLinks]] routes chat links within their originating tab, and the default prompt encourages descriptive links to useful page passages.

Pane listing and page reads return references carrying a pane ID and an HTTP(S) destination URL. Section references use real page anchors from observed IDs or named anchors. On click, Bend validates the destination and navigates the cited pane when it still belongs to the chat's tab. If that pane is gone, it uses the tab's existing [[Sources/BrowseCore/Session.swift#BrowserTab#commandClickPaneID|designated link pane]], or its sole remaining pane. Multiple panes without a designated destination leave a stale citation unavailable; another tab's panes are never navigated.

Navigation uses WebKit, including the fragment, without querying selectors or injecting scrolling JavaScript. Older selector-based references request a fresh link, and unsupported schemes or embedded credentials remain rejected even when falling back. Ordinary HTTP(S) links focus a matching page in this tab, otherwise reuse its designated link pane or sole pane, otherwise open a neighboring pane. Reuse preserves pane and WebView identity. Custom system prompt overrides remain unchanged.


## Transcript scrolling

[[Sources/Browse/ChatInlineText.swift#ChatScrollFollow]] suspends automatic bottom-following during user scrolling and keeps the reading position when the user stops above the latest response.

Returning to the bottom or pressing Latest resumes following streamed text. Latest is a compact glass pill centered above the composer, with text at 80% of the standard button size. Stable transcript layout avoids lazy row height estimation during updates. [[Sources/Browse/ChatInlineText.swift#ChatInlineText]] uses selectable native text with an explicit link delegate forwarding clicks to the chat's URL handler, including pane citation schemes.

[[Sources/Browse/ChatSidebar.swift#ChatSidebar]] keeps Clear chat and Close chat in a fixed header without a visible glass background. The transcript viewport spans the panel, scrolling beneath both the toolbar and floating composer. [[Sources/Browse/ToolbarScrollFade.swift#ToolbarScrollFade]] starts fading messages below the toolbar and fully hides them by its midpoint, without adding a visible header surface. Top content clearance keeps the first message below the toolbar when scrolled to the start. [[Sources/Browse/FloatingPanelBackground.swift#FloatingPanelGlassView]] uses configurable Liquid Glass with background-only darkening in [[Sources/Browse/FloatingPanelBackground.swift#FloatingPanelBackground]] and blocks clicks on underlying links while foreground input and buttons remain interactive. [[lat.md/architecture/settings#Floating panel appearance]] describes the live appearance controls shared with the media player. The composer’s outside and bottom insets share the same pane-gap value on either window edge. Its measured height supplies scroll-content clearance and positions Latest above it, so the final message remains readable as the editor grows.

## AI debugging

[[Sources/Browse/AIDiagnostics.swift#AIDiagnostics]] provides opt-in local tracing through Settings → Development, with immediate persistent enablement and controls to reveal or clear the logs.

Run and tool lifecycle events and citation clicks, navigation targets and failures share timestamps, process-run IDs, sequence numbers, and tab/pane identities. Prompts, response bodies, tool input text, credentials, URL query values, and fragments are excluded; URL paths and exact citation selectors remain available for diagnosis. Nothing is uploaded. The shared bounded file writer stores ai.jsonl and ai.previous.jsonl in the profile's AIDiagnostics folder, each capped at 500 KiB. Disabling drains writes and preserves existing logs; clearing removes both segments.

## Streaming transcript

[[Sources/Browse/TabChat.swift#TabChat#consume]] displays tool calls with running, completed, error, or stopped state and collapsible arguments and bounded results in conversation order.

Tool calls use compact, content-width capsule buttons with a subtle fill and border. Search queries and page-read ranges appear inside the pill; Read page is singular and shows a chunk number until the result supplies its exact character range. Metadata-only chunks are labelled Links & controls with their part number; text reads show Page text with a character count or range. Clicking a pill expands the same rounded container around its details. [[Sources/Browse/ChatSidebar.swift#ChatActivityRow]] caps the detail viewport at 260 points with internal scrolling, while short details fit their contents. The header and any pending action buttons stay outside that scroll area. Search sources omit a repeated host subtitle when the title is already the host. Tool arguments use labeled fields with a captured page title or address instead of its UUID, and validated pagination part numbers instead of opaque cursors; malformed or overflowing model-supplied indices fall back to generic labels; tool status appears as a small progress or result icon. A completed run without answer text displays a retryable error. Assistant text bubbles begin with the first nonempty text delta; no placeholder bubbles are created between model steps. Bend requests provider-supported reasoning summaries from the native adapters. Known recent Claude models use adaptive summarized thinking, older Claude 4 models use a bounded budget, and supported OpenAI models use automatic summaries. Astra requests high reasoning effort so Gateway supplies summary text; this may increase response latency and token use. Only the latest nonempty paragraph of the returned thinking summary appears as a rolling text block beneath tool calls until the answer starts, then immediately above its response bubble. That position remains fixed during streaming and late tool metadata updates. New steps replace its contents when their summaries arrive; completion retains it, while a new request or clearing chat resets it. The UI neither synthesizes reasoning nor requires models to expose it. [[Sources/Browse/AIModelSearchField.swift#AIModelSearchField]] routes native search-field Up/Down, Return, and Escape commands to highlighted model selection, submission, and dismissal; filtering resets the highlight and keyboard selection scrolls into view.

## Web search

[[Sources/Browse/AISettings.swift#AISettings]] persists a Web Search switch, enabled by default, which applies to subsequent chat turns through [[Sources/Browse/TabChat.swift#TabChat#send]].

The SDK chooses Anthropic Messages for Claude and OpenAI Responses for OpenAI models, both through Vercel Gateway with the existing key and billing. Other models retain Gateway-hosted Perplexity search. For other providers, reported server-tool counts appear as completed disclosures without invented queries or sources. Native search events update pills by server call ID, with query text, status, errors, and clickable source titles/domains. Responses retains encrypted reasoning and output items, except Gateway-incompatible search replay items which become reported query/source context; Messages retains signed reasoning and search blocks for follow-ups to the same model. These opaque payloads are never displayed. External answer and source links use the existing tab-scoped link routing. Turning search off omits it from subsequent turns without cancelling an in-flight request.

## Account sign-in

[[Sources/Browse/AIOAuth.swift#AIOAuthAccounts]] manages provider OAuth credentials and renewal. OpenAI sign-in uses ChatGPT plan authorization; Gateway keys remain an independent fallback.

[[Sources/Browse/AIOAuth.swift#AIOAuthAttempt]] creates fresh PKCE, state, and nonce values. The system browser returns to a bounded, single-use listener bound only to IPv4 loopback. Callback path, port, state, duplicate parameters, and the issued client ID are validated before code exchange. Cancellation and timeout close the listener. Malformed, oversized, and disconnected requests release their connection slots; incomplete connections expire after five seconds so they cannot permanently exhaust the listener. [[Sources/Browse/AIOAuth.swift#OAuthIdentity#verify]] validates RS256 signatures against the provider’s HTTPS JWKS and checks issuer, audience, nonce, subject, and expiry.

OpenAI dynamically registers Bend with a stable per-installation host ID. The issued client ID is retained if code exchange fails and across logout. Access, refresh, and ID tokens, granted scopes, and verified identity are stored together in a profile-specific Keychain item, separate from the legacy Gateway key. OpenAI plan usage requires its explicit granted scope. Refresh is serialized, rotates credentials together, and cannot restore a session after logout. Logout stops requests, clears local tokens, and attempts remote revocation with a retry; an unconfirmed revocation is reported.

[[Sources/Browse/AISettings.swift#AISettings]] exposes account login, account selection, and logout. The active connection controls catalog discovery and model requests; OpenAI’s account-specific visible model slugs go directly to its public Responses API. Switching connections stops active runs and refreshes model choices. [[Sources/Browse/AIOAuth.swift#AIAccountTransport]] refreshes bearer credentials before each model request and restricts them to the configured HTTPS host. SDK transport refuses redirects and uses ephemeral, cookie-free sessions.

Vercel OAuth requires Bend’s registered public client ID, authentication method none, and callback http://127.0.0.1:17849/auth/callback. It uses the app access token directly for Gateway requests with the chosen team slug, rather than provisioning another key. Its login control is not exposed in the connection picker. The client registration and live Vercel flow have not been verified. OpenAI uses an ephemeral callback port with the stable /auth/callback path.

The protocol follows [OpenAI’s account authorization guide](https://developers.openai.com/siwc/token-sharing-open-source/sign-in) and [Vercel’s authorization server API](https://vercel.com/docs/sign-in-with-vercel/authorization-server-api).

Responses adapters retain completed output-item events even when the terminal output array is empty, and deduplicate repeated items by ID. Only successful terminal completion releases local tool calls. AI debugging records per-model text/reasoning character counts and tool-call counts, without recording their contents.

## Saved chat history

[[Sources/Browse/ChatHistory.swift#ChatHistoryStore]] retains conversations on disk, shared across regular windows. Private windows use a separate nonpersistent store and cannot open chat history.

Each conversation is an atomic, owner-readable JSON file under AIChats beside the root session file. It includes visible text, tool details, returned reasoning summaries, draft, selected model, timestamps, and the tab’s URLs, split layout, and focused pane. Updates are throttled during streaming and flushed on send, completion, session saves, and closure. Unreadable files are preserved with a visible error. Credentials and opaque provider replay payloads are excluded; resumed requests use portable user/assistant text and fresh pane context, without replaying tool actions.

[[Sources/Browse/ChatHistoryView.swift#ChatHistoryView]] provides searchable conversation cards grouped by last activity date, message previews, deletion, and Restore. The Show AI Chat History command sits immediately after View History in the command palette and opens bend://chats, reusing an existing history pane. [[Sources/Browse/ChatHistory.swift#BrowserStore#restoreChat]] creates a new tab and independent conversation with the saved split fractions, URLs, focus, and messages. Pane identities and message citation links are remapped, leaving live tabs untouched. Restoring pages reloads their URLs, not their previous DOM or navigation stacks.

[[Sources/Browse/BrowserStore.swift#BrowserStore#newTab]] initializes native page tab titles from [[Sources/BrowseCore/Session.swift#AddressResolver#nativePageTitle]], so chat history appears as AI Chat History in the sidebar immediately. Session startup repairs generic New tab titles for named native pages while retaining custom titles and the start page's New tab label.

[[Sources/Browse/BrowserStore.swift#BrowserStore#save]] records each tab’s active conversation and open/closed chat panel state in its window session. Startup reconnects saved messages, including closed panels, and reopens previously visible panels. Closing the last window retains that state even when the shared store later saves preferences. Chat-visibility observers only queue persistence; extension synchronization runs after the enclosing tab operation has restored valid selection and layout. Runs do not resume automatically. Clearing history cancels matching live runs and resets their messages; generation checks and deletion tombstones prevent delayed stream updates from recreating removed chats. Time ranges remove whole conversations by last activity; clearing all also removes unreadable chat files.

## Chat panel sizing

[[Sources/Browse/SidebarResizing.swift#SidebarResizeHandle]] also resizes chat from its canvas-facing edge, with mirrored window-coordinate dragging and an eight-point hit region.

[[Sources/Browse/BrowserStore.swift#BrowserStore#chatWidth]] defaults to 360 points and persists per window. Bounds derive from the sidebar: the same 200-point minimum and 1.5 times its 400-point maximum. Nonfinite stored widths use the default. [[Sources/Browse/ChatHeaderButton.swift#ChatHeaderButtonAnchor#placeButton]] tracks the current panel width; narrow headers use smaller labelled buttons, and narrow left panels put controls below the window traffic lights. Resizing updates the retained page canvas without replacing its controllers.
