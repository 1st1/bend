# Extension catalog and settings

Curated extension installation and native extension settings windows.

See [[lat.md/tests/extension-hosting/catalog-tests|Test coverage]].

## Extension settings

[SettingsWindowController.swift](../../../Sources/Browse/SettingsWindowController.swift) provides Bend's own Settings window through Command-comma and pane extension menus. It manages web extensions without opening or modifying Safari preferences.

The 1Password card in [[Sources/Browse/ExtensionCatalogView.swift#ExtensionCatalogView#card]] reminds users to add Bend from Applications through the desktop app’s Settings → Browser → Add Browser. The reminder appears before and after installation.

Settings uses a native split view with an always-visible sidebar for UI, Websites, Extensions, and Development. The window uses full-size content with no separate centered window title. Its plain section heading sits over the detail scroll view. At the top, the titlebar is transparent with no separator; scrolling content underneath enables the native frosted backing and subtle separator. Scroll geometry drives both the window transparency and the quickly animated scroll-edge effect. Supported macOS versions use a bounded blur at the top edge. Native window controls sit above compact sidebar rows. The sidebar and detail respect native safe-area insets, keeping their separation aligned through the toolbar without extra backgrounds or forced top-edge offsets. The right pane has a native toolbar title reflecting the selected sidebar section, bridged from SwiftUI into its AppKit window. The title stays visible above the scrolling content; forms and catalog own their margins without extra top spacers or duplicate section titles. [[lat.md/tests/settings-tests#Settings section toolbar]] verifies native toolbar integration and title changes across all sections. UI is selected initially; each section displays its controls in the detail area. The pane menu’s Manage Extensions action targets Extensions through [[Sources/Browse/SettingsWindowController.swift#SettingsWindowController#show]], including when Settings is already open or reopened. General Settings commands preserve the current section. [[Sources/Browse/SettingsWindowController.swift#SettingsNavigation]] shares sidebar selection between the window controller and SwiftUI. Dimming, darkening, and glow-intensity sliders use continuous tracks without tick marks, with whole-percentage readouts. The sidebar supports keyboard selection and stays fixed at 200 points wide; its divider cannot resize it. Matching native split-item thickness bounds enforce the width beyond SwiftUI’s content sizing, and the sidebar cannot collapse. [[Sources/Browse/SettingsWindowController.swift#FixedSettingsSidebar#SidebarConstraintView]] observes the native split-item constraints and restores them when SwiftUI resets them after initial layout or section changes. Long settings pages scroll independently. The Settings window has a fixed width of 880 points and remains vertically resizable. Every presentation centers it in the active browser screen’s usable area, overriding saved or previously dragged positions; an oversized restored height is capped to that screen. The hosted SwiftUI layout fixes the width and supplies both native size bounds, so changing sections cannot loosen the constraint. [[lat.md/tests/settings-tests#Settings close shortcut]] covers focused-window closure without changing browser panes. Development exposes the opt-in [[lat.md/architecture/developer-tools#Native input diagnostics|input and pane logging]] toggle. Extensions shows only the three [[lat.md/architecture/extensions/catalog#Curated extension catalog|curated packages]], with installation, enablement, permissions, options, diagnostics, update status and removal in each card. There are no Discover/Installed subviews, general package-import controls, or Update from File button. [[lat.md/architecture/extensions/extension-updates#Extension updates]] provides manual and scheduled update checks with optional automatic installation. General store browsing is not implemented. Load failures remain visible; runtime errors are included in Copy Diagnostics. Every supported macOS version meets the extension host’s minimum OS requirement.

The enable switch reflects whether WebKit loaded the context, not whether every extension feature works. Installed cards show their version without redundant installation or desktop-connection status labels; pending imports retain their status. [[Sources/Browse/ExtensionManager.swift#ExtensionManager#compatibilityNotice]] shows 1Password warnings for failed signing or Hardened Runtime checks, without a general experimental-support banner.

The Extension Settings button uses [[Sources/Browse/ExtensionManager.swift#ExtensionManager#settingsPageURL]] to prefer a manifest-declared options page, with identity-matched [[Sources/Browse/ExtensionCatalog.swift#CatalogExtension#settingsPage|catalog routes]] for 1Password and Dark Reader, whose packages omit that declaration. Settings open in the extension's own configured window, reuse an already open page, and require enablement. Unrelated packages receive no fallback based on their display name. [[lat.md/tests/extension-hosting/catalog-tests#Curated extension settings pages]] covers routing and lifecycle.

## Curated extension catalog

[ExtensionCatalog.swift](../../../Sources/Browse/ExtensionCatalog.swift) defines a bundled, curated collection with package-specific installation routes and official publisher descriptions.

[ExtensionCatalogView.swift](../../../Sources/Browse/ExtensionCatalogView.swift) provides three fixed cards with publisher and category information, source links, installation state, enable switches, and inline management controls. Each card shows the official description once beneath its name: the installed package’s localized description when available, otherwise the bundled English description from its pinned package. Package type, installed version, and a successful “Up to date” result appear as compact pills at the card’s top right. Update failures and actionable update controls remain below; compatibility instructions and compatibility badges are omitted. uBlock Origin Lite's Safari package downloads directly from the official GitHub release archive, without an App Store app. The catalog retains its Safari identity for existing installations. Firefox 1Password has confirmed toolbar vault access and remaining autofill and desktop-unlock limitations. Safari 1Password is not offered as its catalog package. Dark Reader uses its Firefox package; dark styling and global and per-site toggles pass the isolated compatibility test.

uBlock Origin Lite is offered only as its Safari package. [[lat.md/tests/extension-hosting/compatibility-tests#Safari uBlock Lite compatibility]] covers real request blocking, popup filtering controls, Safari detection, and disable/re-enable behavior in isolation. Advanced filtering is not fully verified.

Initial installations use pinned official packages and SHA-256 digests: GitHub’s Safari archive for uBlock Lite and Mozilla-hosted packages for 1Password and Dark Reader. Downloads use an ephemeral session, a size limit and timeouts, require a successful HTTPS response, and validate the digest before import. [ExtensionManager.swift](../../../Sources/Browse/ExtensionManager.swift) checks the expected package identity before persistence, rejects duplicate identities, and cleans temporary downloads. Failed or cancelled downloads do not install a package. Catalog entries are matched to installed records by package identity, never display name. Imported packages remain disabled with no granted access until the user enables them and approves permissions. [[lat.md/architecture/extensions/extension-updates#Extension updates]] discovers subsequent stable releases from those same publishers and replaces installed copies without changing their identity or grants.

The [[docs/ublock-package-comparison.md|uBlock package comparison]] documents same-version Safari and Mozilla differences. Safari ships WebKit-specific rule and CSS adaptations absent from Mozilla. [[Sources/Browse/ExtensionManager.swift#ExtensionManager#makeContext]] assigns only the Safari uBlock Lite package identity a registered Safari-style origin, so its detector selects WebKit behavior. Other extensions retain Bend's original scheme. The extension UUID and native storage namespace stay stable; [[Sources/Browse/ExtensionManager.swift#ExtensionManager#restoredExtensionURL]] maps saved uBlock pages from the former scheme after restoration. The compatibility bridge accepts both extension schemes with its existing origin and permission checks. Packages are not rewritten. [[lat.md/tests/extension-hosting/extension-updates-tests#uBlock origin migration and isolation]] covers preserved settings, saved pages, and unrelated-package isolation. Basic smoke-test success does not establish advanced filtering compatibility or performance parity.
