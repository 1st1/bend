# Extension updates

Owned extension packages, update checks, and resource migration.

See [[lat.md/tests/extension-hosting/extension-updates-tests|Test coverage]].

## Extension updates

[[Sources/Browse/ExtensionUpdater.swift#ExtensionUpdater]] checks installed curated extensions at browser startup and every four hours, with a Check for Updates button and an automatic-installation toggle in Extensions settings.

The shared production manager starts the scheduler through [[Sources/Browse/BrowserStore.swift#BrowserStore#extensions]]. Checks wait for restoration, coalesce concurrent requests, and run independently of browsing. Network fetches and package copying do not block the main thread; only the validated context replacement holds the extension-management lock. Checks record their completion time and per-extension results; one source’s failure does not stop other extensions. Settings persists the automatic-installation preference, which defaults on, and the last check time. Turning it off leaves discovered releases available through each card’s Update button. Startup restores per-extension check results cached for four hours, including release metadata and failures, and requests only missing or expired results. Cached releases reconstruct available updates against the current installed version. The manual button always fetches fresh metadata; periodic checks use elapsed wall time, including sleep. Future-dated cache entries are ignored. Service refusals name GitHub or Mozilla and remain inline until a subsequent check.

[[Sources/Browse/ExtensionUpdater.swift#ExtensionUpdateSource]] queries Mozilla’s public add-on API for 1Password and Dark Reader. For Safari uBlock, it follows GitHub’s public latest-release redirect and reads the release asset list without using the REST API or authentication. [[Sources/Browse/GitHubReleasePage.swift#GitHubReleasePage]] validates the official repository, numeric release tag, exact Safari ZIP link, and a unique SHA-256 checksum attached to that filename. Missing, ambiguous, or changed markup rejects the check rather than guessing. The HTML parser does not execute scripts or load external entities. Mozilla metadata must identify the expected public package, bounded size, approved HTTPS download host, and SHA-256 digest. Metadata responses are capped at one MiB; downloads retain their size bound, checksum, package identity, and manifest-version verification. Both use ephemeral sessions and timeouts. [[Sources/Browse/ExtensionUpdater.swift#ExtensionVersion]] compares dotted numeric versions and rejects downgrades, equal versions, and unfamiliar version syntax. Source contracts are documented by [Mozilla](https://mozilla.github.io/addons-server/topics/api/addons.html) and [GitHub](https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases); GitHub’s asset HTML is validated defensively because it is not a stable API.

[[Sources/Browse/ExtensionManager.swift#ExtensionManager#applyCatalogUpdate]] rechecks the installed revision after downloading and verifies the downloaded manifest version and package identity before replacement. The existing transaction preserves UUID, origin, enablement, approved grants, and native extension storage; new access leaves the updated extension unloaded for permission review. Download or validation failures retain the old installation. Removal or manual replacement during download invalidates the pending update. Noncatalog packages have no update controls in Settings.

The Safari ZIP lacks a bundle identifier, so [[Sources/Browse/ExtensionManager.swift#ExtensionRecord]] persists catalog provenance supplied only by the verified download path. [[Sources/Browse/ExtensionManager.swift#ExtensionManager#packageIdentifier]] uses it with the Safari manifest declaration to retain uBlock’s existing identity and Safari origin, without rewriting upstream resources. Manual file replacement cannot assign that provenance. An equal-version update is allowed once for an existing Safari app-bundle installation to migrate it to the direct archive.
