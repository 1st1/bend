# Extension compatibility

Native messaging and browser API adapters for supported extensions.

See [[lat.md/tests/extension-hosting/compatibility-tests|Test coverage]].

## Native extension messaging

[ExtensionNativeMessaging.swift](../../../Sources/Browse/ExtensionNativeMessaging.swift) bridges WebKit native-message delegates to Firefox-compatible desktop helpers without sharing Safari's extension state.

The host resolves user then system Mozilla NativeMessagingHosts manifests, validates names, stdio transport, executable paths, and the requesting Gecko ID against allowed_extensions. Only loaded, registered contexts with nativeMessaging permission can connect. Launch arguments contain the real manifest path and extension ID; Bend remains the parent application with its own signature.

Persistent ports and one-shot replies use length-prefixed UTF-8 JSON over pipes. Frames are limited to 1 MiB, queued writes to 4 MiB, and concurrent connections to sixteen per context. [[Sources/Browse/ExtensionNativeMessaging.swift#NativeMessageConnection#start]] performs blocking pipe reads on a dedicated dispatch queue, delivering each chunk synchronously to the main queue for ordered processing and backpressure. Idle helpers cannot exhaust Swift's cooperative worker pool. Reads handle fragmented frames without waiting for the pipe to fill. Invalid input, EOF, write failures, and one-shot timeouts close the session. Payloads and helper stderr are not logged. Disable, removal, replacement, port disconnection, and permission revocation tear down connections and terminate helpers.

The installed 1Password helper is discovered through its Firefox manifest. Desktop unlock requires a qualifying distribution signature and the Bend app to be added through 1Password Settings → Browser → Add Browser, plus desktop integration enabled in the extension. Bend does not alter the trusted-browser list or impersonate Firefox. The transport and real extension's connection request are tested. The helper rejects Apple Development signing; the Developer ID build installed in Applications has user-confirmed desktop integration and Touch ID unlocking. See [[lat.md/architecture/extensions/diagnostics#1Password connection probe]] for the standalone diagnostic limitation. Safari's proprietary app-extension route is not implemented.

## Extension compatibility adapters

[ExtensionCompatibility.swift](../../../Sources/Browse/ExtensionCompatibility.swift) adds notifications, limited privacy settings, and main-frame navigation-target events while preserving WebKit's native event delivery and permission checks.

The controller's extension-only web-view configuration injects the adapter at document start. The native `browser` namespace remains intact so WebKit can dispatch events; the `chrome` namespace forwards native APIs and supplies missing ones. Notification and privacy namespaces are also exposed on `browser`. Ordinary website views receive no adapter, and native message handling rejects non-main frames, foreign origins, unloaded contexts, and missing operation-specific permission. Extension source packages are not patched.

The privacy adapter implements password saving and legacy/address/card autofill service settings using [ChromeSetting's API shape](https://developer.chrome.com/docs/extensions/reference/api/types). Bend has no built-in savers, so reads report false and not controllable, disabling and clearing succeed without changing preferences, and enabling is rejected. Promise and callback forms are supported, with callback errors scoped to `runtime.lastError`; unrelated privacy settings and private scopes are unsupported. Safari preferences are never changed. This prevents Firefox 1Password's saved-account startup path from throwing on its browser password-manager settings calls.

[ExtensionManager.swift](../../../Sources/Browse/ExtensionManager.swift) includes the declared privacy permission in approval and persisted grants because WebKit omits unsupported permissions from its requested-permission set. The adapter checks explicit grants, including expiry and revocation, rather than WebKit's unsupported-permission query. Existing installations without that grant require review before loading with the new capability.

[ExtensionNotifications.swift](../../../Sources/Browse/ExtensionNotifications.swift) delivers basic macOS notifications, requests system authorization when a notification is created, and returns authorization failures to the extension. Notification IDs are scoped to the owning extension. Create, update, clear, enumeration, click, button, and dismissal callbacks are supported for the current session. Up to two buttons and bounded title/message lengths are accepted; richer notification types are rejected. Notifications use Bend's system icon and identify the extension in their title. Disabling, uninstalling, or replacing a context clears its tracked notifications and page registrations. Permission-level changes are checked on visibility changes and periodically while extension pages are alive.

[BrowserStore.swift](../../../Sources/Browse/BrowserStore.swift) records opener relationships for main-frame link openings before publishing the destination tab. [ExtensionBrowserBridge.swift](../../../Sources/Browse/ExtensionBrowserBridge.swift) exposes those relationships through WebKit. The adapter derives `chrome.webNavigation.onCreatedNavigationTarget` from real tab-created events, checking the current navigation permission and URL filters. Unrelated tab creation does not emit this event. Subframe source IDs are unavailable through this host's public navigation interface, so subframe openings are excluded rather than mislabeled. The native `browser.webNavigation` namespace is unchanged.

The [compatibility regression tests](../../../Tests/BrowseTests/ExtensionCompatibilityTests.swift) exercise native messaging alongside the adapter, notification scoping and revocation, rejection of website callers, cleanup, and navigation-event identity. The opt-in real-package test follows Firefox 1Password onboarding without entering credentials.

## Firefox browser information and menu settings

[[Sources/Browse/ExtensionCompatibility.swift#ExtensionCompatibility]] supplies browser identity and a constrained context-menu setting to extension pages without claiming Firefox engine compatibility.

The runtime information API returns [[Sources/Browse/ExtensionCompatibility.swift#ExtensionCompatibility#browserInfo|Bend's profile name and bundle version/build]], with explicit development fallbacks for unpackaged runs. Native runtime objects and event delivery remain intact. Promise and callback forms are supported.

[[Sources/Browse/ExtensionCompatibility.swift#ExtensionCompatibility#browserSetting]] reports mouse-down context menus as not controllable. Valid set and clear operations return false because macOS WebKit's event timing is unchanged; invalid values and private scopes are rejected. The adapter exposes only this browser setting, requires the declared browser-settings permission, and checks explicit grants on every call. [[Sources/Browse/ExtensionCompatibility.swift#ExtensionCompatibility#requiredPermissions]] includes this otherwise unsupported permission in approval and persistence; existing installations need permission review before restoration can load them.

[[Sources/Browse/ExtensionCompatibility.swift#ExtensionCompatibility#javascript]] returns false for optional-permission queries for known unavailable capabilities, including clipboard reading and absent bookmarks, history, find, search, containers, and downloads APIs. Remaining permissions and origin arguments still go through native validation. It grants no access and preserves native permission events.

Mouse Gestures for Safari can be imported from its installed App Store app through [[Sources/Browse/ExtensionManager.swift#ExtensionManager#installMouseGestures]]. Bend checks the bundle identity, keeps its own copy, and starts new imports disabled. Its card in [[Sources/Browse/ExtensionCatalogView.swift#ExtensionCatalogView]] uses the same prominent Install in Bend action, icon, publisher, and package/version badges as catalog downloads. If the app is missing, installation opens its Mac App Store listing and waits without blocking other extension actions. Returning to Bend resumes installation once the app is available; active-window polling also handles downloads finishing after return. Cancel stops the pending import. The App Store app need not be enabled in Safari. The installed card offers manual refresh from the app after App Store updates; the catalog updater does not update this local package. The extension uses standard tab and messaging APIs without native-helper calls. The tab bridge maps the exact Safari new-tab URL `favorites://` to Bend's start page. [[lat.md/tests/extension-hosting/compatibility-tests#Safari mouse gestures]] exercises a real right-button leftward gesture.

Foxy Gestures' options can load and save settings through these adapters. [[Sources/Browse/ExtensionManager.swift#ExtensionManager#compatibilityNotice]] explains that default right-button gestures require unsupported mouse-release menus and that Firefox-specific commands remain limited. See [[lat.md/tests/extension-hosting/compatibility-tests#Extension browser information and menu settings]] and [[lat.md/tests/extension-hosting/compatibility-tests#Foxy Gestures options smoke test]].
