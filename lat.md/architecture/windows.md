# Browser windows

Native application windows, fullscreen transitions, and window dragging.

See [[lat.md/tests/windows-tests|Test coverage]].

## Application shell

[BrowseApp.swift](../../Sources/Browse/BrowseApp.swift) owns menus, keyboard shortcuts, and application lifetime. [BrowserWindows.swift](../../Sources/Browse/BrowserWindows.swift) owns the browser windows. [BrowserView.swift](../../Sources/Browse/BrowserView.swift) renders a dark sidebar, vertical tabs, pane controls, and start pages.

Both built-in start pages show a centered, muted-gray keyboard shortcut reference matching the browser's menus. Action labels and right-aligned keys form two columns, grouped by task with whitespace; shorter panes scroll the list. Tab, window, and pane shortcuts appear by default. A centered, subtle gray See more pill reveals navigation, find, page zoom, history, and settings shortcuts; See less collapses them again. Expansion and collapse smoothly resize the list, fade the extra groups, and rotate the chevron. The pill keeps a stable width and animates as one unit while its labels crossfade; Reduce Motion disables these animations.

The sidebar presents one continuous column of tabs without group headings or group creation. Each tab contains one or more browser panes. Selection changes the displayed tab; closing the final tab creates a replacement. The sidebar can be resized or hidden, with session-save errors shown at the bottom only when needed. The tab scroll area reaches the bottom edge in both docked and floating sidebars, or the media/error footer when present. Its opacity mask fades rows to transparent at that edge over [[Sources/Browse/BrowserView.swift#Chrome#sidebarScrollFadeHeight]], with no fixed gap below the fade. Matching scroll-content padding lets the final row scroll fully above the fade. The top edge also fades beneath favorites, or beneath the header when there are no favorites. This fade grows with the scroll offset up to the same height and disappears at the start, keeping the first row fully opaque. Favorite-to-list spacing belongs to the scrolling content so no fixed gap separates the favorites from the fade.

The sidebar header right-aligns downloads beside the sidebar toggle and hides downloads when its list is empty. The header sits above the clipped sidebar scroll view and shares the tab list’s insets, aligning the toggle’s right edge with the tab rows. Docked rows use ten points on the outer edge and four toward the canvas; the canvas’s six-point gap completes the matching visible margin. Floating sidebars use ten points on both sides. Command-T and the File menu create tabs; there is no plus button. Panes use six-point outer margins and divider gaps. When the sidebar is hidden, downloads remains beside the sidebar toggle near the window controls in the upper-left visible pane, including when a different pane is zoomed. Both layouts keep Downloads on the left and the sidebar toggle on the right, with matching 28-point controls and a two-point gap. [[lat.md/tests/downloads-tests#Downloads with collapsed sidebar]] covers their visibility, sizing, and spacing.

Each pane has one compact title row with Back/Forward, reload/stop, extensions, zoom, and close controls, using shared [[lat.md/architecture/pane-controls#Toolbar button styling]]. The split-pane button is omitted; splitting remains available through menus and shortcuts. Reload focuses its pane and becomes stop while loading; it is disabled on start pages. The persistent address row is replaced by the [[lat.md/architecture/address-entry#Location popup]]. [[lat.md/architecture/pane-controls#Pane navigation controls]] describes toolbar visibility and navigation behavior; tab creation remains in the File menu and Command-T.

[BrowserWindows.swift](../../Sources/Browse/BrowserWindows.swift) attaches an empty unified native toolbar to give the traffic lights standard toolbar-height spacing. Each window uses its own toolbar identifier so AppKit does not share fullscreen visibility changes with other or newly opened windows. AppKit manages their placement through resizing and full-screen transitions; their native size and position do not change when the sidebar toggles. Sidebar controls and pane titles share the traffic lights’ fixed vertical centerline, accounting for the pane’s outer margin. The transparent titlebar has no separator or shared toolbar actions. [[lat.md/tests/windows-tests#Window control alignment]] covers sidebar toggles and window resizing.

## Fullscreen chrome

[BrowserWindows.swift](../../Sources/Browse/BrowserWindows.swift) auto-hides the empty native toolbar in fullscreen so it cannot permanently cover the browser’s pane headers and sidebar controls.

[FocusWebView](../../Sources/Browse/BrowserStore.swift) enables WebKit's HTML Fullscreen API for browser pages, including replacement and supplied browser WebViews. Video players can use their fullscreen button or double-click handler without site-specific code. WebKit retains its native user-gesture and iframe permission checks and manages element fullscreen separately from Bend's window fullscreen. [[lat.md/tests/windows-tests#Page fullscreen availability]] checks the page-visible API.

The empty unified toolbar is hidden before fullscreen entry, leaving AppKit's compact native titlebar for top-edge rollover instead of a tall empty toolbar row. The same toolbar becomes visible again after exit or failed entry, preserving windowed traffic-light alignment. Completed transition notifications update a transient per-window fullscreen state. [BrowserView.swift](../../Sources/Browse/BrowserView.swift) then removes the collapsed sidebar’s traffic-light spacer and the narrow sidebar’s extra window-control row, while retaining its sidebar toggle and pane actions. Location popups dismiss before either transition so their anchors cannot remain at obsolete window coordinates. No page or WebView is replaced. [[lat.md/tests/windows-tests#Fullscreen chrome transitions]] covers real fullscreen entry and exit.

## Browser windows

[BrowserWindows.swift](../../Sources/Browse/BrowserWindows.swift) owns independent native browser windows. File → New Window and Command-N create a blank tab in a new window with its address popup focused.

Each window owns its store, tab selection, pane controllers, sidebar sizing, zoom, closed-item stack, address panel, and saved frame. [BrowseApp.swift](../../Sources/Browse/BrowseApp.swift) routes tab, pane, navigation, and history commands to the key browser window, falling back to the last active browser while a popup or Settings is key. Command-W closes the focused utility window, including Settings, instead of falling through to the last browser; the address popup retains its cancel-new-tab behavior. In a browser window, Command-W closes the focused pane while other panes or tabs remain; on the final pane of the final tab it closes that window if another browser window remains. In the sole browser window it replaces the closed page with one blank pane and focuses its address popup, retaining the closed page for reopening. Explicit native window closure closes the window unless a pane is pinned; [[lat.md/architecture/pane-controls#Pinned panes and tabs]] protects pinned panes from close commands. [[lat.md/tests/windows-tests#Closing the last browser pane]] covers this boundary and isolation from other windows. Closing a browser window stops and releases only its page controllers. Live tabs and panes can move between open Bend windows through [[lat.md/architecture/pane-transfers#Cross-window dragging]].

One retained root store owns regular-window history and shared UI preferences, including after its original window closes. Other [BrowserStore.swift](../../Sources/Browse/BrowserStore.swift) instances delegate reads and writes to it and forward observation, so live history results and appearance changes reach every window. Settings and the extension manager are shared; normal website views use WebKit's shared default data store. [[lat.md/architecture/session#Session restoration]] preserves each window's layout independently.

## Window dragging

Empty sidebar and pane-header areas move the browser window, while tab rows, title pills, resize handles, and controls keep their dedicated interactions.

[WindowDragging.swift](../../Sources/Browse/WindowDragging.swift) supplies native mouse targets for empty sidebar and pane-header regions, with explicit control exclusions. Background presses pass through AppKit's normal window event dispatch before the target's mouse-down handler requests native dragging, preserving window activation, shadow, and glass appearance. [BrowseWindow.swift](../../Sources/Browse/BrowseWindow.swift) exposes the native mouse-down dispatch scope for hit testing; it does not start background window drags itself. AppKit may defer a titlebar-background mouse-down until pointer movement crosses its drag threshold. The sidebar target overlays its scroll view but claims only mouse-down, leaving scrolling, hover, and other events to the underlying content. Pane title handles retain their dedicated routing. Traffic lights, sidebar tab rows, pane toolbar buttons, sidebar buttons, and the resize edge are excluded. Empty pane-header presses also focus that pane. Hidden and clipped regions cannot initiate dragging.
