# Settings

Application preferences and per-website settings, storage, and zoom.

See [[lat.md/tests/settings-tests|Test coverage]].

## UI preferences

[SettingsWindowController.swift](../../Sources/Browse/SettingsWindowController.swift) opens Settings on the UI sidebar section, with link-opening, active-pane highlighting, and independent window/header glass controls.

[BrowserStore.swift](../../Sources/Browse/BrowserStore.swift) saves shared UI preferences in the root session file; secondary windows delegate to that store. Command-click offers a new pane to the right (the default), one dedicated pane per tab, or a new tab. Changes apply to existing controllers immediately. Older sessions preserve their previous new-pane/new-tab choice. Ordinary new-window links continue opening tabs. Pane and tab destinations preserve main-frame opener tracking. [[Sources/Browse/BrowserStore.swift#BrowserStore#commandShiftClickDestination]] independently configures Command-Shift-click as New tab (the default), New pane, or New window in Settings → UI → Links. Both WebKit navigation-policy and new-window callbacks recognize Command-Shift-left-click before ordinary Command-click, cancel source navigation, and use the live shared preference. Only activated HTTP(S) links qualify; download actions retain their existing handling. New tabs insert below the active tab, and new panes open beside the clicked source without reusing its dedicated Command-click pane. [[Sources/Browse/BrowserWindows.swift#BrowserWindows#openLinkInNewWindow]] opens a separate foreground window containing one destination pane, with no blank tab or address popup, and persists its membership. Missing preferences default to New tab, independent of older Command-click choices. [[lat.md/tests/link-navigation-tests#Command-Shift-click destinations]] covers routing, isolation, and persistence.

[[Sources/Browse/BrowserStore.swift#BrowserStore#optionClickDestination]] independently configures Option-click (Alt-click) as New tab by default, New pane, or New window under Settings → UI → Links. It uses the shared [[Sources/BrowseCore/Session.swift#LinkOpenDestination]] choices, persists as an optional session field, and applies live across windows. [[lat.md/architecture/link-navigation#Option-click event routing]] handles Option-left-click on HTTP(S) links before WebKit's default download behavior; Command and Control combinations retain their existing routing. Unmodified downloads remain unchanged. [[lat.md/tests/link-navigation-tests#Option-click destinations]] and [[lat.md/tests/link-navigation-tests#Native Option-click links]] cover preferences, native events, iframe origins, and popup targets.

In dedicated-pane mode, the first Command-click creates a pane to the right of its source. Later Command-clicks anywhere in that tab navigate and focus the same pane, retaining its WebView and navigation history. The pane identity persists in the tab across restarts. Closing or moving it away clears the designation; the next click creates a replacement. If closing or moving another pane leaves the dedicated pane alone, it becomes ordinary without reloading; the next Command-click creates a new destination. Restoring an older single-pane tab also clears a stale designation. Reopening the closed pane restores its designation if no replacement exists. Joining tabs keeps the destination’s designated pane, or adopts the source’s when the destination has none. Clicking from the dedicated pane reuses itself without a self-opener; iframe links clear any previous main-frame opener. [[lat.md/tests/link-navigation-tests#Dedicated Command-click pane]] and [[lat.md/tests/link-navigation-tests#Command-click preference migration]] cover reuse and compatibility.

[PaneHighlight.swift](../../Sources/BrowseCore/PaneHighlight.swift) persists the highlight mode, separate outline/glow/title-tint colors, outline gap and width, glow intensity and spread, and title-tint intensity. Title tint defaults to blue at 30% intensity when selected; older records retain their existing mode and receive these additional defaults. Older highlight records without spread retain their former intensity-derived radius. The outline gap defaults to 0.5 pt for new or older records without a gap; thickness defaults to 2 pt. None is the default for new sessions, missing highlight settings or mode, and Reset to Defaults; explicitly saved modes remain unchanged. Settings show only controls relevant to the selected mode; switching modes retains their values. The Panes section resets all highlight modes and their retained values together with inactive-pane dimming; its reset button is disabled when everything matches the defaults. The reset control and preference getter share the dimming default defined in [BrowserStore.swift](../../Sources/Browse/BrowserStore.swift). Preferences are shared across windows and update mounted panes without replacing WebViews. Nonfinite values fall back to defaults and numeric values are bounded. [[lat.md/tests/session-tests#Mounted tab switching]] checks page hit testing in every style.

Inactive-pane dimming, available in Transparency mode, ranges from 0% to 100%, defaults to 8%, and updates all mounted panes immediately. Values are clamped and nonfinite edits are ignored. [Session.swift](../../Sources/BrowseCore/Session.swift) stores optional fields so older session files retain their tabs and receive defaults for missing preferences. [[lat.md/tests/settings-tests#UI preference persistence]] and [[lat.md/tests/link-navigation-tests#Configurable link destination]] cover persistence and routing.

On macOS 26 and later, Browser window and Pane headers each offer Regular/Clear style, optional custom sRGB tint, a 0–100% darkening slider, and an independent reset. Defaults preserve untinted Regular glass, with 40% window darkening and 50% header darkening. Changes apply live to every existing native browser window and mounted header. [GlassAppearance.swift](../../Sources/BrowseCore/GlassAppearance.swift) stores each appearance in optional session fields and normalizes numeric values; older sessions keep their content and receive defaults. Pane headers also offer independent continuous top- and bottom-rim clipping sliders over [[Sources/Browse/BrowserStore.swift#BrowserStore#headerRimClippingRange|0–16 pt]] in the same section. Defaults are [[Sources/Browse/BrowserStore.swift#BrowserStore#defaultHeaderTopRimClipping|0.5 pt top]] and [[Sources/Browse/BrowserStore.swift#BrowserStore#defaultHeaderBottomRimClipping|1.1 pt bottom]]. Zero restores the corresponding native glass rim; larger values hide more of it. Values persist separately in the session, are shared across windows, and update native web headers, stacked headers, and the mini player live without changing controls or content insets. The underlying live-pane material shares the top clipping. Pane-header Reset to Defaults resets both values with the glass appearance. Older sessions receive missing defaults; explicit saved clipping values remain unchanged. Values are bounded and nonfinite edits are ignored. Legacy custom separator settings are ignored; no custom line or line-color controls remain. Pane headers additionally offer Solid color with only an opaque color picker; tint, darkening, and rim controls are hidden in this mode. The selected color persists independently of glass settings when switching styles, and reset restores the regular-glass defaults. [[Sources/BrowseCore/GlassAppearance.swift#GlassAppearance]] migrates legacy Regular/Clear records and supplies the missing solid color. Blur and refraction remain system-controlled for glass styles. [[lat.md/tests/settings-tests#Live window glass preferences]] covers native updates without content replacement.

## Page zoom

[BrowseApp.swift](../../Sources/Browse/BrowseApp.swift) routes page zoom shortcuts to the focused visible web pane in the active browser window, using WebKit's native page zoom.

Command-plus and Command-equals zoom in, Command-minus zooms out, and Command-zero resets to 100%. View menu actions use bounded steps from 25% to 500%, disabling at the limits. Start/history pages, errors, hidden panes, and unrelated key windows are excluded. Zoom affects page content without resizing browser chrome, reloading the document, or changing the separate Zoom Pane layout mode. Zoom changes are saved through [[lat.md/architecture/settings#Website settings]] and applied to other open panes on the same hostname. Navigation restores the destination website’s override or the default, including after redirects, back/forward, and app restarts. Command-zero saves an explicit 100% override when the default differs. [[lat.md/tests/settings-tests#Page zoom shortcuts]] covers keyboard routing and limits.

Trackpad pinch uses WebKit’s native magnification, enabled for every page WebView including replacements. This smooth, pointer-centered magnification stays local to the page and does not change the saved website page zoom or other panes.

## Website settings

[WebsiteSettings.swift](../../Sources/BrowseCore/WebsiteSettings.swift) models a default page zoom and hostname overrides. [WebsiteSettingsStore.swift](../../Sources/Browse/WebsiteSettingsStore.swift) shares the preferences across browser windows.

HTTP and HTTPS pages share settings across paths and ports on a lowercase hostname, with trailing dots normalized. Subdomains remain independent, including www. International names use Foundation's ASCII hostname representation. Internal pages and extension documents have no stored website zoom and use 100%.

[BrowserStore.swift](../../Sources/Browse/BrowserStore.swift) injects the same settings store into each page controller. Fresh web views and native internal pages receive zoom immediately. Reused web views keep the outgoing document’s zoom and settings ownership throughout provisional navigation; main-frame commit applies the final destination’s preference after redirects or history traversal. Failed or cancelled provisional loads leave the outgoing zoom intact. [[lat.md/tests/settings-tests#Website zoom during provisional navigation]] covers the transition. Preference changes update matching mounted or hidden WebViews without reloading. Subframe navigation cannot change the top-level zoom. [[lat.md/tests/settings-tests#Website setting identity]] and [[lat.md/tests/settings-tests#Website zoom navigation and sharing]] cover matching and lifecycle behavior.

Settings opens on UI and includes a Websites section. [WebsiteSettingsView.swift](../../Sources/Browse/WebsiteSettingsView.swift) offers a default zoom, a filterable hostname list with zoom pickers and individual resets, and a reset of all overrides. Filtering starts as a Filter by name button. Clicking it focuses a compact, softly filled field; clicking outside, Return, or Escape ends editing. An empty unfocused field returns to the button, while a nonempty query remains visible and active. Choosing the current default removes that website's override; changing the default leaves existing explicit overrides intact. Clearing browsing history does not clear these settings. Read/save errors appear in this section with Retry; failed writes preserve the prior saved preferences, while a keyboard zoom change can remain temporary in the current pane. [[lat.md/tests/settings-tests#Website settings failure recovery]] covers safe recovery.

## Website security preferences

[[Sources/Browse/WebsiteSettingsView.swift#WebsiteSettingsView]] exposes public WebKit security and privacy controls in Settings → Websites, backed by [[Sources/BrowseCore/WebsiteSettings.swift#WebsiteSettings]].

Fraudulent-site warnings and JavaScript default on; HTTP warnings and blocking all cookies default off. [[Sources/Browse/BrowserStore.swift#PageController#applyWebsiteSecurity]] updates native fraud warnings and cookie policy on existing website views. Cookie blocking retains existing stored data. Navigation preferences apply JavaScript and HTTPS policy on subsequent loads without automatically reloading open pages. HTTP warnings use WebKit’s HTTPS upgrade with user-mediated HTTP fallback; system exceptions remain WebKit-controlled. Extension documents retain their own scripting preferences.

Regular windows share persistent preferences. Private windows inherit a temporary copy, consistent with website zoom settings. [[lat.md/architecture/privacy#Privacy preferences]] owns cookie controls and native tracking, payment disclosure, and ad measurement settings. IP-hiding, Reader, and private-tab-lock switches are not exposed. [[lat.md/tests/settings-tests#Website security preferences]] covers native preference updates and real page script execution.

## Website data management

[[Sources/Browse/WebsiteDataView.swift#WebsiteDataView]] lists and filters WebKit website-data records for the Settings window’s data store, with confirmed removal of individual sites or all listed records.

Removal covers cookies, caches, and other WebKit storage without changing Bend history, downloads, or website preferences. Private windows manage only their own ephemeral store; regular windows manage the shared profile store. Removal and refresh disable conflicting operations while work is in progress.

## Website settings database

[WebsiteSettingsDatabase.swift](../../Sources/BrowseCore/WebsiteSettingsDatabase.swift) stores website preferences in a separate WebsiteSettings.db beside the root session and History.db, using the system SQLite library.

Schema version 3 adds tracking, payment disclosure, and ad measurement preferences; tracking prevention and payment disclosure default on, while ad measurement defaults off. Earlier security and zoom choices survive migration. [[lat.md/tests/privacy-tests#Privacy settings migration]] covers version 2 upgrades. [[lat.md/tests/settings-tests#Website security migration]] covers migration and persistence; security changes participate in the same atomic transactions as zoom changes.

One shared store owns the connection and cached settings. A singleton defaults row and hostname-keyed website rows store page zoom, bounded from 25% to 500%. Schema versioning rejects newer or unrelated databases; corrupt storage is preserved instead of overwritten. Saves update changed rows in a transaction with WAL and full synchronous commits. The cache advances only after commit, so failures roll back and can be retried. Website settings are browser preferences, separate from WebKit cookies, localStorage, and IndexedDB. [[lat.md/tests/settings-tests#Website settings transactions]] and [[lat.md/tests/settings-tests#Website settings storage protection]] cover persistence and failure boundaries.
